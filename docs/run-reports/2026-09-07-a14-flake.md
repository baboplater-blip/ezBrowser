## 4. 못 한 것과 이유

| 항목 | 사유 |
|------|------|
| **실패를 직접 재현해 원인 확정** | 재현율이 약 1/5 이고, 수정 후에는 재현되지 않는다. **"가장 그럴듯한 원인을 구조적으로 제거했다"**가 정확한 표현이며, "원인을 규명했다"고 쓰지 않는다 |

## 5. 다음 업그레이드 제안 3개

1. **시나리오 간 DOM 격리를 규칙으로** — 이번 문제의 뿌리는 A14 하나가 아니라 **모든 시나리오가
   한 페이지를 공유**하는 구조다. 각 시나리오 시작 시 페이지를 알려진 상태로 되돌리는
   공통 `resetPage()` 를 두면 같은 부류의 flake 가 구조적으로 사라진다. 규모 S~M.

2. **메모리 페이지가 `perf-history.json` 을 읽게** (임무 9·10 제안 유지) — 실측값 하드코딩 해소. 규모 S.

3. **`verify:full` 요약을 status.md 에 자동 추기** — 요약 마크다운이 이미 파일로 저장되므로,
   라운드 로그에 붙이는 것까지 스크립트화하면 "기록 없는 검증"이 구조적으로 불가능해진다. 규모 S.

## 부록 — 왜 기준을 낮추지 않았나

제안은 내가 임무 10에서 쓴 것이었다: *"오클릭 0 + 입력 정확 + 도달 ≥9/10 으로 바꾸면 흔들림이
사라진다."* 막상 코드를 열어 보니 **의도된 폴백은 A6가 이미 검증**하고 있었고, A14에서 폴백을
허용하면 "빠른 프로파일에서도 실제 입력이 전달되는가"라는 이 시나리오의 질문 자체가 사라졌다.
**흔들림의 해법이 기준 완화인 경우는 드물다** — 대개는 테스트가 통제하지 못한 상태가 있다.
