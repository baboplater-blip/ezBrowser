# 귀환 보고서 — 조건부 완료(expect 가드)로 LLM 호출 줄이기

임무: 에이전트가 "행동 1스텝 + 완료 확인 1스텝" 으로 작업당 최소 2번 모델을 부르던 것을, 완료 확인을 **모델 호출 없는 로컬 검증**으로 대체해 줄인다. 앞 임무(CLI 세션 유지)의 후속.
등급 T2 · 종결 범위 push까지 · 브랜치 `auto-dev/hygiene-sync`.

## 1. 한 일

- **`app/main/features/ai/agent.ts`**
  - 신규 액션 `expect {text?, urlContains?}`(파서·tool spec·프롬프트 규칙 JSON/tool 양쪽). 모델이 `[click, expect, done]` 처럼 주 동작 뒤에 붙이면, 주 동작이 **일반 실행 경로에서 성공**하고 `!publishish && risk.level==='none'` 일 때만 꼬리(`pendingTail`)와 **동작 전 관찰 기준선**(`pendingTailBase`)을 보관.
  - 다음 루프 상단에서 `guardPasses` 를 **로컬 판정** → 통과하면 `skipLlm` 으로 모델 호출·history push 를 건너뛰고 후속 동작을 **기존 액션 경로**(읽기전용 블록·통합 위험 게이트·정직한 done·발행금지)로 흘려보냄. 실패하면 꼬리를 버리고 안내를 붙여 평소대로 모델에 묻는다.
  - 판정 방식: **"동작 전 관찰에 없다가 새로 나타났는가"**(부정어 12자 근접 출현 제외 · 입력 value 제외 · `urlContains` 는 URL 이 실제로 바뀐 경우만). 후속은 정확히 1개, ref 가 필요 없는 동작(`done·navigate·scroll·wait·note`)만. expect 를 붙일 수 있는 주 동작은 `click·type·navigate·scroll`(일반 실행 경로) — 그 밖에는 경고 후 무시. 인젝션 탐지된 페이지에서는 가드 불신.
  - 프롬프트: 처음엔 "붙여도 된다"(허용형) → 실제 claude 가 전혀 쓰지 않아 **"작업의 마지막 동작에는 기본으로 붙여라"(지시형)** 로 교체.
- **`app/main/features/ai/page-actions.ts`** — 액션 union 에 `expect`, `urlContains` 필드.
- **`build/verify-agent-loop-cdp.mjs`** — B1~B5 추가(통과→호출 1회 / 실패→재질의 / 가드 뒤 ref 동작 거부 / 동작 전부터 있던 문구 오탐 방지 / 부정문 오탐 방지) + `run()` 이 상태 문구를 되돌리도록 수정.
- **`build/bench-agent-efficiency-cdp.mjs`** — 실행별·합계 **LLM 호출 수** 열 추가.

## 2. 내린 결정과 이유

- **로컬 판정을 "포함" 이 아니라 "새로 나타남" 으로** — 리뷰어가 짚은 대로 단순 포함은 동작 전부터 있던 버튼 라벨("제출")·메뉴 문구("완료")·부정문("완료되지 않았습니다")에 속아 **잘못된 완료 보고**로 직결된다. 기준선 대비 출현 횟수 증가 + 부정어 근접 제외로 바꿨고, B4·B5 가 그 두 오탐을 상설 검사한다.
- **후속 정확히 1개, ref 없는 것만** — 새 페이지에서 옛 ref 로 클릭하는 오동작을 원천 차단(B3). 2개 이상이면 조용히 버려지던 것을 명시 거부로.
- **발행성·위험 동작 뒤엔 가드 미보관** — 게시·결제·삭제 뒤에는 반드시 모델이 새 화면을 보게 한다(정직한 done 경로 유지).
- **가드 통과 시 `pendingPrefix` 교체** — `wait` 후속처럼 프리픽스를 안 쓰는 동작이 오면 2스텝 전 결과가 낡은 채 다음 호출에 붙던 것(리뷰 H2) 방지.
- **L7(탭 조작) 1회 실패는 간헐로 분류** — 초기 탭 수가 1로 계측된 실행에서만 실패, 즉시 재실행 22/22. 이번 변경은 탭 코드를 건드리지 않았다.

## 4. 못 한 것과 이유

- **T1 유형(결과 문구를 모르는 클릭)의 호출 절감** — 모델이 기대 문구를 못 쓰면 가드를 못 붙인다. "URL 변경" 또는 "요소 상태 변화(disabled→enabled)" 같은 문구 없는 가드는 다음 라운드 후보.
- **비일반 경로 동작(key Enter·click_at·upload 등) 뒤의 가드** — 경고만 하고 미지원. 흔한 "Enter 로 제출" 패턴은 `type submit:true` 로 대체 가능.
- **관찰 diff 전송(바뀐 요소만)** — 계획 2번의 나머지 절반. 세션 모드에선 캐시 읽기라 시간 이득이 작아 이번 범위에서 제외.

## 5. 다음 업그레이드 제안 3개

1. **문구 없는 가드** — `expect{urlChanged:true}`·`expect{ref 상태 변화}` 로 T1 유형까지 1호출화. 판정은 이미 기준선 비교라 확장이 쉽다.
2. **실사이트 레시피에 가드 내장** — 네이버 발행 레시피처럼 인스타·유튜브 게시 흐름을 만들 때 "게시 완료 문구" 를 레시피가 지정해 모델 판단 없이 가드가 붙게 한다(모델 채택률 의존 제거).
3. **벤치 이력 추세** — 이번 라운드처럼 프롬프트 한 줄로 호출 수가 오가므로, `bench-efficiency` 결과를 이력으로 쌓아 프롬프트·CLI 업데이트에 따른 회귀를 감시.
