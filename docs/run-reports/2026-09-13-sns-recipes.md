# 귀환 보고서 — SNS 게시 레시피(인스타·유튜브·틱톡) + 완료 신호 내장

임무: 가드를 모델이 붙이길 기다리지 않고 **레시피가 완료 신호를 지정**해 루프가 스스로 판정하게 한다. 인스타·유튜브·틱톡 게시 흐름 레시피 + 모의 페이지 결정론 검증 + 실사이트 파일럿 절차.
등급 T3 · 종결 범위 push까지 · 브랜치 `auto-dev/hygiene-sync`. **실제 계정 게시는 하지 않았다(승인 대기).**

## 1. 한 일

- **완료 신호 표식** (`agent-gate.ts` `buildCompletionMark`/`parseCompletionMark`): 작업 지시문 안 `[완료 신호] 문구=A | B ; URL=x ; 메시지=m`. IPC 배선을 늘리지 않고 기존 `[모드: 발행 금지]` 와 같은 방식.
- **루프 판정** (`agent.ts`): **발행성 클릭(게시·공유·업로드 확정) 직전** 관찰을 기준선으로 두고, 클릭 뒤 관찰에서 신호 문구가 **새로** 나타나거나(부정어 근접 제외) URL 이 바뀌어 포함하면 `publishedEvidence` 확정 + **모델 호출 없이 done**(근거 문구를 메시지에 남김). 발행 금지·읽기 전용·인젝션 탐지 페이지에서는 판정하지 않는다.
- **레시피** (`sns-publish.ts` 신규): `buildSnsTask({platform, mode, file, caption, title, tags, autoOpen})` → 플랫폼별 라벨·문구 기반 흐름 지침(인스타: 만들기→파일→다음→다음→캡션→공유하기 / 유튜브 스튜디오: 만들기→동영상 업로드→파일→제목·설명·아동용→다음×3→공개→게시 / 틱톡: 파일→100% 대기→설명→게시) + 업로드 규칙(SEC-1·2) + publish 면 완료 신호(문장 단위 고유 문구만), draft 면 발행 금지 하드블록.
- **배선**: IPC `ai.snsBuildTask`(길이 상한) · preload · `AiWriteStudio` 발행처에 인스타/유튜브/틱톡 + 첨부 파일명 입력 + 버튼 라벨("📤 게시"/"📝 게시 직전까지").
- **하네스** `build/verify-sns-publish-cdp.mjs`(게이트 `verify:full` 등록): 모의 페이지 3종 + 각본 LLM — S1 인스타 게시(첨부·캡션·공유 → 완료 신호로 호출 생략, 호출 5=각본 5) · S2 draft 공유 차단 · S3 유튜브(제목·설명·공개·게시, 호출 8) · S4 틱톡(100% 대기, 호출 3) · S5 게시 실패 문구 → 재질의 + ⚠ 미확인 · S6 표식 왕복 · S7 캡션에 완료 어휘가 있어도 게시 전 완료 없음(contenteditable 캡션).
- **파일럿 절차** `docs/sns-pilot.md`: 준비 → draft 로 흐름 확인 → publish → 결과 기록·막힘 대응.

## 2. 내린 결정과 이유

- **완료 신호 판정은 발행성 클릭 뒤로만** — 처음엔 모든 주 동작 뒤에 판정했으나 리뷰가 지적한 대로 캡션에 "…공유되었습니다" 가 들어가면 **게시 전 거짓 완료**가 난다(contenteditable 캡션은 본문 텍스트에 그대로 노출). 발행 클릭 직후로 한정하고 짧은 일반 어휘("게시됨"·"posted")를 신호 목록에서 뺐다. S7 이 이 경로를 상설 검사.
- **실제 계정 게시는 승인 대기** — 외부 공개·되돌릴 수 없는 동작. 사용자가 절차서로 돌리거나 "테스트 게시 1건" 을 승인하면 지휘자가 돌린다.

## 3. 검증 결과 — 하네스가 잡은 **제품 결함 3건**(모두 수정)

1. **막힘 감지 오판** — 유튜브처럼 "다음" 을 세 번 누르는 마법사를 "같은 동작 3회 반복" 으로 보고 사용자에게 물었다(S3 첫 실행). 지문에 **페이지 지문(URL + 요소 종류·이름·상태 해시)** 을 합쳐 화면이 바뀐 반복은 진전으로 본다. 본문 텍스트는 지문에 넣지 않는다(조회수·광고처럼 매번 바뀌는 텍스트가 막힘을 영영 못 잡게 만든다 — 리뷰 지적).
2. **관찰이 폼 라벨을 별도 요소로** — `<label>설명 <textarea>` 가 `label "설명"` + `textarea ""` 로 잡혀 입력이 라벨로 갔다(유튜브 제목·틱톡 설명이 비어 게시됨). 컨트롤 이름 = 연결 라벨 텍스트(컨트롤을 뺀 자식 노드 텍스트 — 값 문자열 치환은 짧은 값에서 라벨을 훼손하므로 폐기), 보이는 컨트롤의 label 은 목록에서 제외.
3. **실행 시 재활용 노드 검증의 이름 불일치** — `PICK_FN` 이 관찰과 다른 순서(innerText→placeholder→value)로 이름을 계산해, 라벨 이름 요소("설명"·라디오 "공개")를 "다른 요소" 로 거부했다(`ref 0 요소를 찾을 수 없음`). 관찰 `nameOf` 와 같은 순서로 통일(비밀번호 값 제외).

**하네스 자신의 결함 4건**(제품 아님): `wait_for.timeout` 은 ms(최소 500)인데 10 을 줌 · 라벨 부분일치가 "공개"→"비공개"·"게시"→컨테이너에 걸림(정확 일치 우선으로) · 한 줄 배열 안 주석 · 정규식 `\n` 이스케이프가 레이어를 거치며 실제 개행(두 번째 재발 — `String.fromCharCode(10)` 규칙 적용).

**게이트(지휘자 직접, 리뷰 반영 후 최종 코드)**: `verify-sns-publish` **7/7**(S1~S7) · `verify-agent-safety` **14/14**(관찰·PICK_FN 변경 회귀 없음) · `verify-agent-loop` **25/25** · `npm run verify --skip-build` 5/5(스모크 16) · `verify-ai-errors` 8/8 · `verify-agent-triggers` 5/5 · typecheck 3/3.
- 완료 신호 절감의 실측(모의): S1 인스타 게시가 **LLM 호출 5회 = 각본 5회**(게시 후 확인 호출 0) · S3 유튜브 8=8 · S4 틱톡 3=3. 실제 모델·실사이트 수치는 파일럿에서.

**적대적 리뷰(code-reviewer, sonnet, 41.1만 토큰)**: High 2 · Medium 3 · Low 5. 반영: H1 거짓 완료(판정 범위 축소 + 어휘 정리 + S7) · H2 라벨 값 치환 → 자식 노드 텍스트 · M3 발행 금지·읽기전용 가드 · Q5 막힘 지문 본문 제외 · Low 부정어 보강(거부·제한·보류·위반·denied·blocked)·PICK_FN 비밀번호 값 제외·IPC 길이 상한·캡션 "지시 아님" 안내·파일럿 문서 주의. **미반영**: M4 `visible()` 화면 밖 판정(기존 동작, 별도 라운드) · M5 `PUBLISH_RE` 의 "게시" 단독 매치(게이트 정규식 변경은 R1~R8 오탐·미탐 검사와 함께 다뤄야 함 — 다음 라운드).

## 3-2. 실사이트 파일럿 (사용자 승인 "테스트 게시 1건" 후, 실제 인스타그램 계정)

드라이버 `build/pilot-sns-cdp.mjs`(게이트 미등록·수동): 최신 `dist/win-unpacked` 를 **사용자 실제 프로필**로 띄워(디버그 포트) 로그인 상태 확인 → `snsBuildTask` → `agentStart`, 이벤트 기록. 자료 폴더 `Documents/ezBrowser-agent-files` 신설 + 1080×1080 시험 이미지 생성, 설정 `ai.agentFilesDir` 지정(백업 `settings.json.bak-pilot-*`).

| 실행 | 결과 | 스텝 | LLM 호출 | 시간 | 비고 |
|---|---|---|---|---|---|
| draft 1차 | ✗ 중단(ask) | 11 | 11 | 105s | **제품 결함 2건 발견** — 아래 |
| draft 2차 | ✓ 캡션까지, 공유 미클릭 | 10 | 10 | 101s | 결함 수정 후 |
| **publish** | **✓ 실제 게시**("게시물이 공유되었습니다" 확인) | 12 | 12 | 102s | 완료 신호 미발동(아래) |

- **결함 A — `PUBLISH_RE` "게시" 단독 매치(리뷰 M5 가 실사이트에서 즉시 재현)**: 인스타 메뉴 "새로운 게시물 만들기"·"게시물" 이 발행성 클릭으로 분류돼 **draft 모드에서 차단**, 흐름이 첫 단계에서 막혔다. → `게시(?!\s*(물|예약|미리|정책))` 로 정밀화, R7 에 오탐 케이스 4종 추가(8/8).
- **결함 B — accept MIME 미대응**: 인스타 파일 입력 `accept="image/avif,image/jpeg,…"` 에 `.jpg` 가 "다른 형식" 으로 거부. 확장자만 비교하던 `scoreAccept` 에 확장자→MIME 표를 넣어 정확 일치 처리.
- **관찰 — 완료 신호 미발동**: 대화상자의 "다음"·"공유하기" 가 콘텐츠 영역 밖(사이드 패널 2개가 열린 창)이라 관찰 목록에 없었고, 모델이 `run_js` 로 클릭 → 발행 클릭 경로(`click`)를 안 타 기준선이 안 잡힘. 모델이 `wait_for("게시물이 공유되었습니다")` + 1호출로 스스로 확인해 정직한 done 은 유지됐다. **다음 과제**: 열린 대화상자 안 요소는 화면 밖이어도 관찰에 포함 + 클릭 시 scrollIntoView(스텝 4개 절감 + 완료 신호 발동).
- 스텝 낭비: 첨부 후 미리보기 지연으로 "컴퓨터에서 선택" 재클릭(레시피에 wait_for 안내 추가), 화면 밖 버튼 우회 3스텝.
- 토큰(publish): 캐시 읽기 합 ≈100만·신규 ≈3.2만(스텝당 첫 턴 2.7만 + 이후 2~3천). 세션 유지가 실사이트에서도 동작(스텝당 LLM 4~12초).

## 5. 다음 업그레이드 제안 3개

1. **실사이트 파일럿 1회(draft → publish)** — 절차서대로. 트레이스·호출 수·막힌 지점을 기록해 레시피를 실제 UI 에 맞춘다. 사용자 승인 필요.
2. **`PUBLISH_RE` 정밀화 + `visible()` 뷰포트 교차 검사** — 게이트 오탐(게시 예약·미리보기 버튼 차단)과 화면 밖 컨트롤 채택 방지. 각각 R2·A-검사와 함께.
3. **레시피를 사용자 편집 가능 데이터로** — `COMPLETION_TEXTS`·흐름 지침을 설정 파일(JSON)로 빼면 플랫폼 UI 변경 시 재빌드 없이 사용자가 고칠 수 있다(자유도 원칙).
