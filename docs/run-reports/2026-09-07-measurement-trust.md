## 2. 내린 결정과 이유

| 결정 | 이유 |
|------|------|
| **A/B 도구가 "차이 없음"을 스스로 선언하게** | 사람이 두 숫자를 눈으로 비교하는 순간 같은 실수가 반복된다. 중앙값 차이가 산포 이내면 도구가 **주장하지 말라고 못 박는다** |
| **같은 구성끼리 A/B 하는 자기검증부터** | 도구가 "차이 없음"을 실제로 말하는지 확인하지 않으면 도구를 믿을 수 없다 |
| **기준선을 5회가 아니라 누적 10회로** | 한 세션의 5회는 그 세션 상태에 묶인다. 이력에 쌓아 중앙값을 보는 편이 안전하다 |
| **회수 시계 값을 실측 후에도 줄이지 않음** | 실측(스모크 17초 vs 한도 10분)은 여유롭지만, 느린 머신·부하 상태를 겪어 봤다. 한도를 조이면 그때 거짓 실패가 난다 |
| **예산 250MB 는 여전히 건드리지 않음** | 3라운드째 같은 원칙 |

## 3. 검증 결과

### ② A/B 자동화 (`build/perf-breakdown.mjs --ab`)
```bash
node build/perf-breakdown.mjs --ab --runs 4 \
  --a-label default  --a-settings '{}' \
  --b-label ai-off   --b-settings '{"ai":{"enabled":false}}'
```
- A/B 를 **교대로** N회 실행 → 각 구성의 중앙값·최소·최대·산포를 표로
- **판정 규칙**: `|중앙값 차이| ≤ 관측 산포` 면 **"차이 없음 — 이 데이터로 기여도를 주장하면 안 된다"** 를 출력하고, 표본을 늘리라고 안내
- 결과는 `ab-result.json`(verdict 포함)

**자기검증** — 같은 구성을 A/B 로 돌림(차이가 없어야 정상):
| 구성 | 표본 | 중앙값 | 산포 |
|------|------|--------|------|
| same-A | 2 | 255 | 2 |
| same-B | 2 | 250 | 6 |

→ 겉보기 -5MB 차이. 도구는 **"차이 없음"** 으로 판정했다. 이것이 임무 4·5에서 내가 두 번 빠진 함정이고, 이제 코드가 막는다.

### ① 기준선 확정 (조용한 머신, 누적 10회)
```
warm 표본: 253, 254, 251, 250, 249, 250, 249, 250, 251, 250
warm 중앙값: 250MB · 범위 249~254MB
```
- 부하를 없앤 뒤(모든 앱 종료 + 60초 대기) 5회 연속: **249·250·249·250·251** — 산포 **±1MB**
- 즉 **측정은 신뢰할 수 있다.** 임무 5에서 본 ±13MB(233~260MB)는 내가 하네스를 연달아 돌려 만든 **자기 유발 부하**였다
- 결론: **웜 빈 창 RSS = 250MB, 예산 250MB — 여유 0**. 그래서 게이트가 실행마다 PASS/FAIL 을 오간다(실제로 이번 라운드에도 252MB FAIL, 250MB PASS 둘 다 나왔다)
- 이 정밀도라면 **V4(226MB) 대비 +24MB 증가는 실재**로 보는 편이 타당하다(임무 5 보고서에서 유보했던 판단을 여기서 갱신한다). 다만 **출처는 여전히 미상**이며, AI 레이어는 A/B 로 배제됐다

### ③ `verify:full` 완주 — 단계별 실측
| 단계 | 상태 | 소요 | 현재 회수 시계 |
|------|------|------|----------------|
| typecheck / build / package | PASS | 4s / 4s / 8s | 5m / 10m / 15m |
| smoke (16종) | PASS | 17s | 10m |

- 유일한 실패는 perf 예산이고, 그건 **제품 사실**이지 하네스 결함이 아니다(위 ①)
- 견적(20~40분) 대비 실제 **9분** — `verify:full` 은 생각보다 싸다. 라운드 종료 시 습관적으로 돌릴 만하다

### 부수 — perf 이력 경로 통합
`verify-all` 은 단계별 `--out`(verify-out/all/perf)을 넘기므로 이력이 그쪽에 쌓여 **게이트 실행은 항상 "과거 표본 0개"** 였다(추세선이 갈라짐). 이력을 저장소 고정 위치(`perf-out/perf-history.json`)로 통일했다. 확인: 게이트 실행에서 `기준선 비교(warm, 과거 9회 중앙값 250MB): +0MB` 정상 출력.

| `git push` / 원격 | **가드레일** — 로컬 커밋만 |

2. **`verify:full` 을 라운드 종결 절차에 명문화** — 9분이면 충분히 싸다. CLAUDE.md 품질 게이트에

   지금은 `npm run verify`(quick)만 권장돼 있다. 규모 S.

3. **perf 판정에 "경계값" 표기** — 250MB 예산에 250MB 측정이면 PASS/FAIL 이 동전 던지기다.
   판정 표에 `여유 0MB (경계)` 같은 경고를 넣어, 통과했더라도 **여유가 없다는 사실**이 보이게 한다.
   지금은 249MB PASS 와 200MB PASS 가 똑같아 보인다. 규모 S.
