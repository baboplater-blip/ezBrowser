## 3. 검증 결과

### ② 다크모드 — 원인 규명과 해소
- **격리 재현기**(탭 3개 + 워크스페이스 왕복 + 토글 5라운드): **15/15 전부 정상**. 앱은 다크모드를 안정적으로 적용한다.
- 스모크에서의 실패는 **무거운 perf 실행 직후**에 몰려 있었다 → 부하 시 메인→렌더러 CSS 반영이 3초를 넘김.
- 조치: 확인 폴링 3초 → **8초**, 그리고 실패 시 **대상 탭 URL + 모든 탭의 filter 값**을 오류에 첨부(다음에 재발하면 어느 탭인지 즉시 안다).
- 검증: 스모크 **6회 연속 16/16**(그중 3회는 perf 직후의 부하 조건에서). 목표(5연속) 충족.
- **정직한 한계**: "앱이 절대 실패하지 않는다"를 증명한 것은 아니다. 부하 상태의 지연을 오탐하지 않게 만들었고, 재발 시 진단이 남는다.

### ① AI 지연 로드 — 전제가 무너져 철회
측정 순서와 결과(전부 `perf-breakdown`, 빈 창 총 private WS):

| 단계 | 측정 | 결론 |
|------|------|------|
| 임무 4 (1회씩) | default 255 / ai-off 240 | "AI ≈15MB" ← **오판** |
| 재현 시도 (2회씩) | default 253·251 / ai-off 257·244 | 재현 안 됨(ai-off 가 더 높기도) |
| 부팅 초기화 A/B (2회씩) | ON 259·258 / OFF 246·240 | 차이가 있어 보임 |
| **표본 확대 (4회씩, 교대)** | **ON 256·256·248·233 / OFF 258·260·257·248** | **차이 없음** |

- 지연 로드를 실제로 구현해 측정했을 때도 252·256MB 로 개선 없음(앱 로그로 **AI 가 실제로 부팅되지 않았음**을 확인한 상태에서).
- **실제 원인**: 이 머신의 빈 창 측정에는 실행 간 **±13MB 드리프트**(233~260MB 관측)가 있고, 그 폭이 예산까지의 여유와 맞먹는다. 2~4 표본은 없는 차이를 만들어 낸다.
- 조치: 구현 전량 되돌림(`app/main/index.ts`·`ipc/ai.ts` 원복, `features/ai/boot.ts` 삭제). typecheck 0.

### ③ perf 기준선 추적
- 실행마다 `perf-out/perf-history.json` 에 `{시각, 경로(warm/cold), 빈창 private, 탭당, 콜드스타트, 표본 폭}` 기록(최근 50회).
- 같은 경로의 과거 중앙값과 비교해 delta 출력, **+10MB 이상이면 경고**. 표본 3개 미만이면 비교를 표시하지 않는다(성급한 판단 방지).
- 검증: 3회 연속 실행 → 3회차에 `기준선 비교(warm, 과거 2회 중앙값 253.5MB): -2.5MB` 정상 출력.

## 5. 다음 업그레이드 제안 3개

1. **조용한 머신에서 기준선 재측정** — 오늘의 최대 장애물은 측정 환경이다(±13MB). 재부팅 직후,
   다른 작업 없이 `perf-measure` 를 5~10회 돌려 `perf-history.json` 에 신뢰할 기준선을 쌓는 것이
   메모리 논의의 **전제 조건**이다. 그 전의 모든 attribution 은 오늘처럼 뒤집힐 수 있다. 규모 S.

2. **메모리 attribution 을 하네스로 자동화** — `perf-breakdown` 에 "A/B 를 N회 교대 실행하고
   중앙값·분포를 비교"하는 모드를 넣는다. 오늘 나는 이걸 손으로 하다 2번 속았다.
   표본 수와 교대 실행을 코드가 강제하면 같은 실수를 막는다. 규모 S~M.

3. **`verify:full` 완주 + 기준선 첫 기록** — 이제 모든 하네스가 개별 통과하고 perf 는 이력을
   남긴다. 한 번 이어 돌려 전 단계 소요·판정을 기록하면 회수 시계 값도 추정치에서 실측으로 바뀐다. 규모 S.

## 부록 — 이번 라운드가 남긴 교훈

**메모리 측정에서 2~4개 표본은 신뢰할 수 없다.** 이 세션에서 같은 빌드가 233~260MB 를 오갔고,
그 폭이 예산 여유와 같았다. 나는 그 위에서 두 번(임무 4의 15MB, 임무 5의 A/B) 잘못된 결론을 냈고,
표본을 늘려서야 바로잡았다. 앞으로 메모리 기여도를 말할 때는 **교대 실행 + 4회 이상 + 중앙값**을
기본으로 한다.
