# i18n 규약 — 외피·내부 페이지·메인 프로세스 다국어

묶음 L0(2026-09-29)에서 만든 다국어 인프라의 사용 규약이다. **대량 문자열 이행은 이 라운드의
범위 밖**이다(약 2,500줄의 하드코딩된 한국어가 외피·pages·main 곳곳에 남아 있다) — 이 문서는
그 이행을 여러 lane 이 **병렬로**, **충돌 없이** 진행할 수 있게 하는 것이 목적이다.

## 요약 (다음 lane 이 그대로 복붙해 쓸 수 있게)

- **지원 언어**: `ko`(기본) · `en` · `vi`. 설정 `ui.language: 'auto'|'ko'|'en'|'vi'`(기본 `'auto'`
  = OS 로케일로 판정, `resolveLocale()` 단일 출처).
- **사전 파일**: `app/shared/locales/{ko,en,vi}.json` — 중첩 JSON, 3개 파일의 키 집합은 **완전히
  일치**해야 한다(`npm run i18n:check` 가 CI/게이트에서 검사).
- **키 네임스페이스(충돌 방지 — 반드시 지킬 것)**:
  | 최상위 키 | 용도 | 담당 |
  |---|---|---|
  | `menu.*`, `action.*` | 네이티브 메뉴·명령 팔레트 액션 라벨(기존, 손대지 말 것) | — |
  | `ui.*` | 외피(브라우저 크롬) React 컴포넌트 — 탭바·툴바·사이드패널 등 **AI 제외** | 일반 렌더러 lane |
  | `ai.*` | AI 사이드바(AiTab 등) 컴포넌트 | AI 담당 lane |
  | `page.<pageName>.*` | `browser://<pageName>` 내부 페이지(정적 HTML) — 예: `page.settings.*`, `page.bookmarks.*` | 그 페이지 담당 lane |
  | `main.*` | 메인 프로세스가 직접 만드는 문구 — 토스트·OS 알림·대화상자 | main 코드 담당 lane |
  | `settings.*` | 예외 — `browser://settings` 는 카테고리가 매우 많아 `page.settings.*` 대신
    `settings.nav.*`/`settings.<category>.*` 로 더 세분화(이미 이렇게 시작됨). 새 카테고리를 만들 때만 따를 것,
    다른 페이지는 `page.<pageName>.*` 를 쓸 것. | settings 담당 lane |

  **충돌 규칙**: 서로 다른 lane 이 같은 최상위 네임스페이스 아래에서 동시 작업할 일이 없도록
  네임스페이스를 lane/영역 단위로 나눴다. 새 페이지·컴포넌트를 이행할 때는 **그 페이지/컴포넌트
  전용 하위 키**를 새로 만들고(`page.newpage.foo`), 다른 네임스페이스의 기존 키를 고치지 말 것
  (같은 문구가 필요하면 새 키를 만들어 값을 복사 — 나중에 한쪽만 바뀌어도 안전).

- **보간 문법**: `{name}` — `t('main.download.completeToast', '✓ {filename} 다운로드 완료', { filename })`.
  키가 없으면 자리표시자를 그대로 남긴다(조용히 사라지지 않음).
- **3개 언어 필수**: 키를 하나 추가하면 ko/en/vi **세 파일 모두**에 넣을 것. `npm run i18n:check`
  가 하나라도 빠지면 비0 종료.

## 각 컨텍스트에서 쓰는 법

### 1) 외피(React 렌더러, `app/renderer/**`)

```tsx
import { useI18nT } from '../i18n'

export function MyComponent() {
  const t = useI18nT() // 언어가 바뀌면 컴포넌트가 자동 재렌더된다
  return <button title={t('ui.toolbar.ai.title', 'AI 어시스턴트 (Ctrl+Shift+Space) — 이 페이지 요약·질문')}>...</button>
}
```

- `useI18nT()` — 반응형 `t(key, fallback, vars?)`. 언어가 바뀌면(설정 변경) 컴포넌트가 재렌더된다.
- `useI18nDict()` — 반응형 평탄화 사전 전체(명령 팔레트처럼 여러 키를 한 번에 조회할 때).
- `useI18nLocale()` — 반응형 현재 로케일(`'ko'|'en'|'vi'`).
- 컴포넌트 밖(콜백·정렬 비교자 등 훅을 못 쓰는 자리)에서는 `import { t } from '../i18n'` 의
  단발성 `t()` 를 쓴다(반응성 없음 — 즉시 값만 필요할 때).
- **fallback 은 항상 한국어 원문**을 넣는다 — 키가 아직 사전에 없거나 오타여도 화면이 깨지지 않는다.

### 2) `browser://` 내부 페이지 (`pages/<pageName>/index.html`, 빌드 없는 순정 HTML/JS)

그 페이지의 CSP 와 head 에 공용 로더를 추가한다:

```html
<meta http-equiv="Content-Security-Policy"
  content="default-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline' browser://shared; img-src 'self' data: https:;" />
<script src="browser://shared/i18n.js"></script>
```

⚠ **호스트 이름에 밑줄(`_`)을 쓰지 말 것** — CSP `script-src`/`connect-src` 의 host-source 문법은
밑줄을 허용하지 않는다(Chromium이 `browser://_shared` 전체를 무효 소스로 **조용히 무시**하고
스크립트 로드를 차단한다 — 콘솔에만 에러가 뜨고 앱은 죽지 않아 원인을 찾기 매우 어렵다. 이번 라운드에서
`_shared` → `shared` 로 개명한 이유). 영문 소문자·숫자·하이픈만 쓸 것.

정적 텍스트:
```html
<span data-i18n="page.foo.title">한국어 원문(그대로 두면 ko 사용자는 깜빡임 없음)</span>
<input data-i18n-attr="placeholder:page.foo.placeholder;title:page.foo.tooltip" placeholder="원문" />
```

동적(JS 템플릿 문자열로 그리는) 텍스트 — **함수 이름을 `t` 로 재선언하지 말 것**(아래 함정 참고):
```js
function trSafe(key, fallback) { return typeof window.t === 'function' ? window.t(key, fallback) : fallback }
// ...
row(trSafe('page.foo.label', '라벨'), trSafe('page.foo.desc', '설명'), ...)
```

언어가 바뀌면 정적(`data-i18n`) 요소는 로더가 알아서 갱신한다. `window.t()` 로 그린 동적 콘텐츠는
재렌더 훅을 건다:
```js
if (typeof window.onI18nChanged === 'function') {
  window.onI18nChanged(() => { try { render() } catch (e) {} })
}
```

**⚠ 함정 — 전역 스크립트에서 `function t(...)` 선언 금지**: `<script>`(비-모듈) 최상위의
`function` 선언은 `window` 의 프로퍼티가 된다. `pages/shared/i18n.js` 가 이미 `window.t` 를
정의해 둔 상태에서 페이지가 안전 래퍼를 `function t(key, fallback) { ... window.t(key, fallback) ... }`
로 선언하면, 이 선언 자체가 `window.t` 를 **자기 자신으로 덮어써** `window.t(...)` 호출이 무한
재귀(`RangeError: Maximum call stack size exceeded`)로 죽는다. 반드시 `t` 가 아닌 다른 이름
(`trSafe`, `tr`, `tt` 등)을 쓸 것.

### 3) 메인 프로세스 (`app/main/**` — 토스트·OS 알림·대화상자)

```ts
import { tMain } from '../i18n' // 상대 경로는 파일 위치에 맞게 조정

ctx.chrome.webContents.send('toast:show', {
  message: tMain('main.download.completeToast', `✓ ${meta.filename} 다운로드 완료`, { filename: meta.filename }),
})
new Notification({ title: tMain('main.download.completeTitle', '다운로드 완료'), body: meta.filename })
```

- `tMain(key, fallback, vars?)` — `currentMainLocale()`(설정 `ui.language` + `app.getLocale()`)로
  로케일을 판정해 조회. main 코드는 fallback 을 반드시 넣을 것(사전 키 오타가 있어도 안전).
- 순환 의존을 피하려고 `app/main/i18n.ts` 는 `app/main/windows/window-service.ts` 등 상위 모듈을
  import 하지 않는다 — main 쪽 다른 파일에서 자유롭게 `import { tMain } from '<상대경로>/i18n'` 하면 된다.

## 언어 전환이 실제로 흐르는 경로 (구현 참고용)

1. **설정**: `ui.language`(`app/main/storage/settings.ts`). `browser://settings` 의 "모양" 카테고리에
   select 로 노출(`ui.language` — auto/ko/en/vi).
2. **메인이 정본을 결정**: `app/main/i18n.ts` 의 `currentMainLocale()` = `resolveLocale(설정, app.getLocale())`.
   `app/shared/i18n-core.ts` 의 `resolveLocale()` 하나가 메인·렌더러·판정 로직 전체의 단일 출처.
3. **외피(새 창)**: `window-service.ts` 가 창 생성 시 `chromeUrl` 에 `&lang=<locale>` 쿼리를 심는다
   (`windowId` 와 같은 패턴) — 렌더러 `App.tsx` 가 **동기적으로** 그 값을 읽어 첫 페인트부터 맞는
   언어로 그린다(깜빡임 없음). 이후 설정이 바뀌면 `i18n:changed` IPC 브로드캐스트로 재로드 없이
   갱신(`useI18nDict`/`useI18nT` 훅이 자동 재렌더).
4. **내부 페이지**: `pages/shared/i18n.js` 가 `internalAPI.i18n.get()` 으로 현재 로케일+사전을 받아
   `data-i18n`/`data-i18n-attr` 요소를 치환하고 `window.t()`/`window.onI18nChanged()` 를 노출한다.
   페이지가 로드되는 순간 한국어 원문이 이미 HTML 에 있으므로 **ko 사용자는 무깜빡임**, en/vi
   사용자만 사전 도착 시 한 번 다시 칠해진다(대량 이행 전까지 감수).
5. **IPC**: `IPC.i18n.get`(`i18n:get`)/`IPC.i18n.changed`(`i18n:changed`) — `handleTrusted` 로 등록되어
   `browser://`·외피(file://)만 호출 가능(콘텐츠 페이지 노출 안 함). 페이로드는
   `{ locale, dict }`(dict 는 평탄화된 `a.b.c` 키 맵).

## 이번 라운드에서 실제로 이행한 예시(참고용 — 패턴을 복사해 확장할 것)

- `pages/settings/index.html` — 좌측 nav 16개 카테고리 라벨(`data-i18n`, `settings.nav.*`) + "모양"
  카테고리의 언어 select 행(`settings.appearance.language.*`, 동적 렌더 → `trSafe()`).
- `app/main/features/context-menu/index.ts` — 북마크 추가 토스트(`main.toast.bookmarkAdded`).
- `app/main/features/downloads/index.ts` — 다운로드 완료/실패 토스트 + OS 알림 제목
  (`main.download.completeToast`/`failedToast`/`completeTitle`, 보간 `{filename}` 사용 예시).
- `app/renderer/components/Toolbar.tsx` — AI·다운로드·명령 팔레트 버튼의 `title`/`aria-label`
  (`ui.toolbar.ai.*`, `ui.toolbar.downloads.*`, `ui.toolbar.palette.*`).

## 검증

- `npm run i18n:check` — ko/en/vi 키 정합성(누락 0).
- `npm run typecheck` — main/preload/renderer 3개 tsconfig.
- `node build/verify-i18n-cdp.mjs` — 실제 패키징 앱을 en/vi/auto 로 시드해 외피 Toolbar title,
  `browser://settings` nav 라벨·언어 select 가 실제로 그 언어로 뜨는지, 설정에서 언어를 바꾸면
  재로드 없이 반영되는지 대조(`npm run verify:full` 에 `i18n` 단계로 등록됨).

## 알려진 한계 / 다음 lane 후보

- **대량 이행 미완**: 외피·pages·main 의 하드코딩 한국어가 대부분 남아 있다(추정 2,000줄 이상).
  이 문서의 네임스페이스 규칙을 따라 페이지/컴포넌트 단위로 나눠 병렬 진행할 것.
- **페이지 로더의 en/vi 깜빡임**: 정적 `data-i18n` 요소는 사전이 도착하기 전까지 한국어 원문이
  보이다가(≈수십~수백ms) 사전 도착 시 다시 칠해진다. 대량 이행 후 체감이 커지면, 메인이 첫 페이지
  로드 응답(`handleBrowserUrl`)에 현재 로케일을 주입해 서버사이드 치환하는 방식으로 개선 가능
  (현재는 순수 정적 파일 서빙이라 하지 않음 — 범위 밖).
- **`ui.language` 변경 시 내부 페이지(이미 열린 tab)의 재조회 지연**: `i18n:changed` 브로드캐스트를
  모든 내부 페이지가 받지만, `render()` 재호출 배선(`onI18nChanged`)은 페이지마다 직접 걸어야 한다
  — 아직 `browser://settings` 한 곳만 배선됨.
- **복수형**: 이번 라운드는 단순화(복수형 규칙 없음, `{count}개` 식 보간만). 필요해지면 별도 규약 추가.
