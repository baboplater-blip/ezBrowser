# ezBrowser 시작하기

3분이면 설치부터 AI 작업까지 갑니다. **이 문서는 2026-09-20 `rc.16` 빌드 기준입니다.**

---

## 1. 설치

두 가지 방법이 있습니다. 둘 다 **관리자 권한이 필요 없습니다**(사용자 단위 설치).

### 방법 A — 설치파일 (권장)

`dist\ezBrowser-0.2.0-rc.16-win-x64.exe` 를 더블클릭하면 끝입니다.
위치를 묻지 않고 설치한 뒤 **자동으로 실행**됩니다(Chrome·Edge 방식).

- 설치 위치: `%LOCALAPPDATA%\Programs\browser-build\`
- 바탕화면·시작 메뉴 바로가기가 생깁니다.
- 제거: 설정 > 앱에서 "ezBrowser" 제거.

> **⚠ 처음 실행할 때 파란 경고창이 뜹니다.**
> 이 빌드는 **코드 서명이 안 되어 있습니다.** Windows SmartScreen 이
> "Windows의 PC 보호" 창을 띄웁니다 → **추가 정보** → **실행** 을 누르면 됩니다.
> 서명 인증서를 넣으면 이 경고는 사라집니다(아래 "아직 남은 것" 참고).

### 방법 B — 설치 없이 폴더째

`dist\win-unpacked\` 폴더를 원하는 곳에 복사한 뒤 안의 `ezBrowser.exe` 를 실행합니다.
레지스트리를 건드리지 않아 USB 에 넣고 다닐 수도 있습니다.

---

## 2. 첫 실행 — 6단계 설정

처음 켜면 설정 화면이 뜹니다. **전부 나중에 바꿀 수 있고, 건너뛰어도 됩니다.**

| 단계 | 무엇 |
|---|---|
| 1 | 기본 검색 엔진 (Google · Naver · Bing · DuckDuckGo) |
| 2 | **데이터 가져오기** — 크롬·엣지·Brave·웨일의 북마크·방문기록을 그대로 옮겨옵니다 |
| 3 | 테마 (시스템 따름 / 라이트 / 다크 / 다크 + 페이지 강제 다크) |
| 4 | 편리 기능 (광고차단 · 마우스 제스처 · 빠른 검색 · 호버 번역) |
| 5 | **AI 연결** — 아래 3번 참고 |
| 6 | 핵심 단축키 안내 |

> 2단계에서 방문기록까지 가져오려면 **원래 브라우저를 완전히 종료**한 뒤 진행하세요.

---

## 3. AI 연결 — 대부분 이미 쓸 수 있습니다

ezBrowser 의 AI 는 **내 계정·내 컴퓨터**로 돌아갑니다. 별도 구독을 새로 팔지 않습니다.

온보딩 5단계(또는 나중에 사이드바 **✨** 버튼)에서 **이 컴퓨터에서 쓸 수 있는 방법을 자동으로 찾아** 보여줍니다.
하나를 고르면 **실제로 한 번 물어봐서 되는지 확인**한 뒤 대화 화면으로 넘어갑니다.

| 방법 | 비용 | 준비물 |
|---|---|---|
| **Claude Code CLI** | 구독 계정 · **추가 요금 없음** | `claude` 설치 + 한 번 로그인 |
| **Codex CLI** | 구독 계정 · **추가 요금 없음** | `codex` 설치 + 로그인 |
| **Gemini CLI** | 구독 계정 · **추가 요금 없음** | `gemini` 설치 + 로그인 |
| **Ollama (로컬)** | **무료** · 외부 전송 없음 | ollama 설치 + `ollama pull llama3.2` |
| Google Gemini API | 무료 티어 | API 키 |
| Claude / OpenAI API | 사용한 만큼 과금 | API 키 |

**이미 쓰고 있는 구독이 있으면 그게 가장 쌉니다** — 목록에서 맨 위에 나옵니다.

### 연결이 안 되면

화면이 **무엇이 문제이고 무엇을 하면 되는지** 그대로 알려줍니다. 흔한 경우:

- *"'claude' 로그인이 필요합니다"* → 터미널에서 `claude` 를 한 번 실행해 로그인하세요.
- *"'claude' 명령을 찾을 수 없습니다"* → CLI 를 설치하거나, `설정 > AI` 에서 실행 경로를 직접 지정하세요.
- *"로컬 Ollama 서버 연결 실패"* → Ollama 가 실행 중인지 확인하세요.

언제든 **설정 > AI > 🩺 상태 점검** 으로 현재 상태를 다시 진단할 수 있습니다.

## 4. AI 로 무엇을 하나

사이드바 **✨** (또는 `Ctrl+Shift+Space`) 를 누르면 세 가지 모드가 있습니다.

- **챗** — 지금 보고 있는 페이지에 대해 묻습니다. 페이지 내용은 토글로 켜고 끕니다.
- **에이전트** — 브라우저를 대신 조작합니다(클릭·입력·이동). 진행 단계가 실시간으로 보이고
  **언제든 중단**할 수 있습니다. **돈·삭제·자격증명이 걸린 동작은 반드시 먼저 물어봅니다.**
- **글쓰기** — 초안을 만들고 다듬습니다. 자동 발행은 하지 않습니다.

대화와 실행 기록은 **재시작해도 남습니다**(로컬 저장).

### 로그인 화면에서 멈추지 않게 — 계정 미리 등록

에이전트가 로그인 화면을 만나면 원래는 **거기서 멈추고 사람을 기다립니다**. 자리를 비운 사이 도는
긴 작업이 로그인 한 번에 통째로 멈추지 않도록, **쓸 계정을 미리 등록**해 둘 수 있습니다.

1. 주소창에 `browser://passwords` (또는 설정 → **🔐 로그인 계정** → "로그인 계정 관리 열기")
2. **＋ 계정 추가** → 사이트 주소(`https://…`) · 아이디 · 비밀번호
3. **"이 계정으로 자동 로그인 허용"** 을 켭니다 — **계정마다 따로 켜야 하고, 저장만으로는 켜지지 않습니다.**

그 다음부터 에이전트는 그 사이트의 로그인 화면을 스스로 통과하고 **원래 하던 작업을 이어서** 합니다.

**이 기능이 지키는 선** (전부 "조금이라도 확실하지 않으면 넣지 않는다"):

| 상황 | 동작 |
|---|---|
| 비밀번호를 AI 모델에게 | **보내지 않습니다.** 브라우저(메인 프로세스)가 직접 입력합니다 |
| `https` 가 아닌 사이트 | 등록도 자동 로그인도 **하지 않습니다** |
| 주소가 조금이라도 다름(서브도메인·다른 포트·비슷한 철자) | **넣지 않습니다** — 정확히 같은 주소일 때만 |
| 가입 폼 · 비밀번호 변경 폼 · 숨겨진 폼 | **넣지 않습니다** |
| 폼이 다른 사이트로 전송되도록 바뀐 경우 | **넣지 않습니다** |
| 아이디 칸이 어느 것인지 모호한 폼 | **넣지 않습니다** |
| CAPTCHA · 인증코드(2단계 인증) | **사람에게 넘깁니다.** 풀거나 우회하지 않습니다 |
| 허용 계정이 여럿인데 기본이 안 정해짐 | 아무것도 입력하지 않고 **물어봅니다** |
| 비밀번호가 틀림 | 성공이라 하지 않고, **3회 연속 실패하면 잠급니다**(계정 잠금 방지) |
| 성공 여부가 애매함 | 성공이라 **주장하지 않고** 멈춰서 확인을 요청합니다 |
| 작업을 정지·취소함 | 그 뒤로 **추가 입력·제출이 없습니다** |

비밀번호는 **OS 암호화(safeStorage)** 로만 저장됩니다. 암호화를 쓸 수 없는 환경이면 **저장 자체를 거부**합니다
(평문으로 저장하지 않습니다). 시크릿 창에서는 새로 저장하지 않습니다.

### 긴 작업 — 오래 걸리는 일 맡기기

에이전트 모드 입력창 위에 **`일반` / `장시간`** 선택이 있습니다.

- **일반** — 25단계·30분 안에 끝낼 일(기본).
- **장시간** — 고르면 **최대 시간**(기본 24시간)·최대 단계·최대 모델 호출 수를 정할 수 있습니다.
  *브라우저를 켜 둔 동안* 그 예산까지 계속 시도합니다.

작업이 시작되면 사이드바에 **작업 카드**가 생깁니다. 거기서 볼 수 있는 것:

| 보이는 것 | 뜻 |
|---|---|
| 상태·경과 시간·단계/구간 | 지금 무엇을 하는 중이고 얼마나 왔는지 |
| 모델 호출 수 / 한도 | 구독 한도를 얼마나 쓰고 있는지 |
| ⏸ 일시정지 | 누른 **그 순간부터 페이지를 더 건드리지 않습니다** (재개하면 그 자리에서 이어감) |
| ⏹ 중단 | 그만둡니다. 이후 클릭·입력·파일 쓰기가 일어나지 않습니다 |
| ⏳ **미완료 — 이어가기** | 예산을 다 썼지만 **끝나지 않았다는 뜻입니다.** 완료가 아닙니다. 누르면 이어서 합니다 |
| 🔍 **완료를 확인해 주세요** | 에이전트가 "다 했다"고 했지만 **결과 근거를 못 댔습니다.** 직접 확인한 뒤 승인하세요 |
| 🔄 재시도 대기 | 네트워크·한도 초과 등으로 잠시 기다리는 중(원인과 남은 시간이 표시됩니다) |

- **사이드바를 닫아도 작업은 계속됩니다.** 다시 열면 카드가 그대로 있습니다.
- **브라우저가 꺼졌다 켜지면** 돌던 작업은 **"중단됨(이어가기 가능)"** 으로 남습니다.
  켜지는 것만으로 저절로 다시 조작하지는 않습니다 — 이어갈지는 사용자가 누릅니다.
- 고급 옵션의 **허용 사이트** 에 도메인을 적으면 그 작업은 **그 사이트 밖으로 나가지 않습니다.**
- 로그인·보안문자(CAPTCHA)는 대신 풀지 않습니다. 막히면 사용자에게 넘기고 기다립니다 —
  직접 처리하신 뒤 "계속" 이라고 하시면 이어서 합니다.

> **⚠ 알아 두실 것:** "다 했습니다" 를 그대로 믿지 않도록 만들었습니다. 결과 근거가 없으면
> 완료로 처리하지 않고 **확인을 요청**합니다. 발행·전송처럼 되돌릴 수 없는 일이 끝났는지
> 불확실하면 **다시 시도하지 않고 멈춰서 묻습니다**(같은 글을 두 번 올리는 것보다 낫습니다).

## 4-B. 이미지를 만들어 SNS 에 올리기 · 관심 블로그에 댓글 달기

### 가장 쉬운 길 — 에이전트 입력창에 그냥 말하기

**`🤖 에이전트`** 입력창에 평소 말하듯 적고 보내시면 됩니다. 양식을 먼저 찾아 들어가실 필요 없습니다.

> `Genspark에서 밤바다 수채화 그려서 내 인스타에 올려줘`
> `등산 관련 블로그 글 3개 찾아서 댓글 달아줘`

이렇게 적으시면 바로 실행하지 않고 **확인 카드**가 먼저 뜹니다.

```
🔗 이 요청을 [이미지 생성 → SNS 게시] 작업으로 실행할까요?
   생성 서비스  Genspark          ← 말씀에서 읽어 채웠습니다
   만들 이미지  밤바다 수채화        ← 고쳐 쓰실 수 있습니다
   게시할 곳    인스타그램
   계정        (직접 입력)         ← 이건 저희가 짐작하지 않습니다
   진행 방식    ● 초안까지만  ○ 게시까지
        [이 작업으로 실행]  [일반 에이전트로 실행]  [취소]
```

- **말씀에서 읽어낼 수 있는 것은 미리 채웁니다** — 어느 사이트에서 만들지, 무엇을 만들지,
  어디에 올릴지, 몇 개를 다룰지.
- **계정은 절대 짐작하지 않습니다.** 어느 계정으로 올릴지는 사용자만 아시는 일이라, 항상 직접
  넣으셔야 하고 비어 있으면 실행 버튼이 눌리지 않습니다.
- **계정을 잘못 넣었어도 처음부터 다시 만들 필요가 없습니다**(`rc.13`). 이미지가 만들어진 뒤
  **확인 단계 카드 안의 "올릴 계정"** 에서 고쳐 **💾 계정 저장** 을 누르면 됩니다 —
  **만든 이미지와 캡션은 그대로 남습니다.** 바꾼 계정이 자동 게시 선승인 범위 밖이면
  그 자리에서 알려 드리고, 게시 전 확인을 받습니다(선승인이 몰래 넓어지지 않습니다).
  다만 **게시가 이미 나갔거나 나갔는지 확인되지 않은 동안에는 잠깁니다** — 그때 계정을 바꾸면
  "내 글인지" 대조 기준이 뒤바뀌어 **같은 글을 두 번 올리는 사고**로 이어지기 때문입니다.
  먼저 "게시 여부 확인" 으로 결론을 낸 뒤에 바꾸시면 됩니다.
- **기본은 늘 "초안까지만"** 입니다. 문장에 "올려줘" 가 있어도 그것만으로 게시 권한이 생기지 않습니다.
- 카드가 마음에 안 드시면 **`일반 에이전트로 실행`** 으로 평소처럼 맡기시면 됩니다.

**이런 문장에는 카드가 뜨지 않습니다**(그래야 맞습니다):

| 적으신 말 | 왜 |
|---|---|
| `인스타에 그림 올리려면 어떻게 해?` | 질문입니다 — 실행 요청이 아닙니다 |
| `블로그 댓글은 절대 달지 마` | 하지 말라고 하신 것을 폼으로 권하지 않습니다 |
| `친구가 "인스타에 올려줘" 라고 했어` | 인용입니다 — 사용자의 지시가 아닙니다 |
| 웹페이지 본문을 통째로 붙여넣기 | 사용자가 타이핑한 지시가 아닙니다 |

> **왜 이 길이 더 안전한가:** 예전에는 같은 말을 적으시면 AI 가 맨몸으로 시도했습니다. 그때는
> **같은 글에 두 번 달지 않는 기록도, 글 수·간격 제한도, 초안 모드도 걸리지 않았습니다** — 그
> 장치들은 이 카드가 만들어 주는 작업 지시에만 붙어 있기 때문입니다. 이제 자연어로 시작하셔도
> 아래 ①·②와 **똑같은 안전장치**를 지나갑니다.

아래 ①·②는 **`🎨 만들어 올리기`** 버튼으로 양식을 직접 채워 시작하시는 길입니다 — 카드로
시작하셔도 그다음 진행은 완전히 같습니다.

### ① 이미지 만들어 올리기 (생성 → 확인 → 게시)

`생성 서비스`(Genspark · ChatGPT · 직접 입력한 주소) + `프롬프트` + `올릴 곳`(인스타그램 ·
유튜브 · 틱톡)을 고르고 **시작**을 누르면 이렇게 진행됩니다.

1. **생성** — 그 사이트로 가서 프롬프트를 넣고 이미지를 만듭니다.
   만들어진 그림을 **이 작업 전용 보관함**에 저장합니다(파일을 어디로 옮기실 필요 없습니다).
2. **확인** — 저장된 **이미지 미리보기**와 **캡션 초안**이 사이드바에 나옵니다.
   캡션은 여기서 고쳐 쓸 수 있습니다. 기본값에서는 **여기서 자동으로 게시되지 않습니다** — 사용자가
   "이대로 게시" 를 눌러야 다음으로 갑니다.
3. **게시** — **브라우저가 먼저 그 탭을 게시할 사이트로 옮긴 뒤**(같은 창·같은 스페이스라
   로그인 상태가 그대로 유지됩니다) 올리고, 끝나면 **게시 영수증**(주소·완료 근거·시각)을 보여 줍니다.
   그 사이에 취소하시거나 선승인을 거두시면 **게시는 시작되지 않습니다** — 이 구간에서는 아직
   아무것도 올라가지 않았으므로, 어떤 순간에 멈추셔도 결과는 "올라간 것 0건" 입니다.

**기본은 "초안까지만"** 입니다. 실제로 올리려면 `게시까지` 를 직접 고르셔야 하고, 고르시면
되돌릴 수 없다는 경고가 함께 뜹니다.

#### 한 번 맡기고 끝까지 — 자동 게시 선승인

매번 확인 클릭을 하고 싶지 않으시면, **시작할 때** `게시까지` 아래의
**`맡기고 자동 게시`** 를 직접 켜십시오. 켜시면 그 자리에서 **최대 건수**와 **유효 시간(분)** 을
정하게 되고, 그 범위 안에서는 캡션 확인 클릭 없이 게시까지 진행됩니다.

- **범위는 시작할 때 못 박힙니다** — 그때 고른 **플랫폼 · 계정 · 건수 · 시간**. 이 범위는
  **사용자 화면에서만** 만들어집니다. AI 도, 방문한 웹페이지도 이 범위를 만들거나 넓힐 수 없습니다.
- **기본값은 여전히 꺼짐**입니다. 아무것도 안 하시면 예전처럼 확인 후 게시입니다.
- 진행 중에 마음이 바뀌시면 **`선승인 취소`** 로 즉시 거둘 수 있습니다.

**선승인을 켜셨어도 자동으로 넘어가지 않는 경우** (이때는 예전처럼 확인을 기다립니다):

| 상황 | 왜 |
|---|---|
| 이미지 후보가 둘 이상이라 사람이 골라야 할 때 | "모호함 없이 확보된 한 장" 이 선승인의 전제입니다 |
| **캡션 생성이 실패했을 때** | 생성 프롬프트를 캡션 대신 올리지 않습니다 — 사유를 보여 드리고 기다립니다 |
| 승인한 것과 **다른 계정·다른 플랫폼** | 범위 밖입니다 |
| 승인 **이전에** 만들어 두셨던 작업 | 예전에 저장해 둔 작업이 나중 승인으로 갑자기 나가지 않게 |
| 정한 **건수를 다 썼거나 시간이 지났을 때** | 범위가 끝났습니다 |
| 초안 모드 · 취소한 작업 | 애초에 게시하지 않습니다 |
| **앱을 껐다 켠 뒤** 확인 대기로 남아 있던 작업 | 재시작 후에는 자동으로 다시 시도하지 않습니다(이미 올라간 것은 영수증으로 판단) |
| **게시 사이트로 옮기는 중에** 취소·선승인 철회·기한 만료가 온 경우 | 그 자리에서 멈추고 "게시는 진행되지 않았습니다" 로 남깁니다 |
| 게시 사이트가 아닌 곳(로그인 리다이렉트 등)에 도착한 경우 | 엉뚱한 사이트에서 진행하지 않습니다 — 직접 확인하신 뒤 다시 시작하시면 됩니다 |
| **옮기는 도중에 앱이 꺼졌을 때** | 다시 켜도 저절로 이어서 게시하지 않습니다(게시는 진행되지 않은 상태로 남습니다) |

> **캡션 실패가 왜 중요한가:** 예전에는 캡션 생성이 실패하면 **이미지 생성 프롬프트를 그대로
> 캡션으로** 썼습니다. 그건 사용자가 쓰지 않은 글이 계정에 올라가는 것입니다. 지금은 올리지 않고
> 실패 사유를 보여 드린 뒤, 캡션을 직접 써 주실 때까지 기다립니다.

#### 만들어 둔 초안을 나중에 올리기 (rc.14 · Publish a saved draft)

`초안까지만` 으로 만들어 두신 작업은 이제 **다시 만들지 않고 그대로 게시로 올릴 수 있습니다.**
예전에는 방법이 없어서 같은 프롬프트로 처음부터 다시 만들어야 했고 — 생성 크레딧을 또 쓰고,
나오는 그림도 캡션도 달라졌습니다. 마음에 들어 확인하셨던 **바로 그것**이 아니게 됐습니다.

카드에서 **`📤 이 초안을 게시하기 / Publish this draft`** 를 누르시면 확인 화면이 열립니다.

```
⚠ 정말 게시할까요? / Publish for real?
   목적지 / Destination   인스타그램 (Instagram)
   계정 / Account         @myaccount
   이미지 / Image         png · 412 KB · sha256 3f9a1c0b77e2…
   캡션                   (올라갈 문구 전문)

   이미지와 캡션은 다시 만들지 않습니다 — 위 내용 그대로 올라갑니다.
   되돌릴 수 없습니다. / This cannot be undone.

   [ 게시 확정 / Publish ]   [ 취소 / Cancel ]
```

- **두 곳에서 올릴 수 있습니다** — 아직 확인 단계에 있는 초안, 그리고 이미 "초안까지 준비"로
  **끝난** 작업 둘 다.
- **누르기 전에는 아무것도 나가지 않습니다.** 확인 화면을 여는 것, 내용을 보는 것, 취소하는 것 —
  어느 것도 게시하지 않습니다. `게시 확정` 하나만이 게시를 시작합니다.
- **확인은 그 화면에 보이는 것에 묶입니다.** 확인한 뒤에 캡션·계정·이미지가 바뀌면 그 확인은
  무효가 되고, **무엇이 바뀌었는지** 알려 드립니다. 다시 확인하시면 됩니다.
- **확인은 한 번만 씁니다.** 버튼을 연타하셔도, 같은 확인을 다시 보내도 게시는 한 건입니다.
- **확인해 둔 채 앱을 끄시면 그 확인은 사라집니다** — 다시 켜도 저절로 올라가지 않습니다.
  (승인은 디스크에 저장하지 않습니다. 저장하면 그게 곧 재시작을 넘어 사는 권한이 됩니다.)
- **자동 게시로 번지지 않습니다.** 한 건을 손으로 확정하신 것이 "앞으로 이 작업은 자동으로 나가도
  좋다" 가 되지 않습니다 — 자동 게시 선승인은 여전히 별개이고, 승격한 작업은 그 대상이 아닙니다.
- **지난 기록은 지우지 않습니다.** "초안까지 준비" 영수증은 카드의 `이전 기록` 에 그대로 남고,
  새 게시 영수증이 그 위에 쌓입니다.

**이럴 때는 올리지 않고 이유를 알려 드립니다** (그리고 **초안은 그대로 남습니다**):

| 상황 | 왜 |
|---|---|
| 계정이 비어 있을 때 | 어느 계정으로 올릴지 정해져야 합니다 |
| 이미 게시가 진행 중이거나, **나갔는지 확인되지 않은** 동안 | 확인 없이 올리면 같은 글이 두 번 올라갑니다 |
| 이미 실제로 게시된 작업 | 두 번 올리지 않습니다 |
| 영수증에 게시 여부 표시가 없는 **예전 판본** | 초안인지 실제 게시인지 알 수 없으면 올리지 않습니다 |
| 보관해 둔 이미지 파일이 지워졌을 때 | 올릴 것이 없습니다(초안 자체는 남습니다 — 이미지만 다시 만드시면 됩니다) |
| 보관 이미지가 처음 확인하신 것과 **달라졌을 때** | 보셨던 것과 다른 그림을 올리지 않습니다 |

> **어떤 그림이 "방금 만든 것" 인지 어떻게 아나:** 생성 버튼을 누르기 전에 화면에 있던
> 이미지를 먼저 기록해 둡니다. 그 뒤에 **새로 나타난** 것만 후보로 봅니다. 로고·광고·
> 썸네일(가로세로 256px 미만)은 후보에서 빠집니다. 그래도 후보가 둘 이상이면 **임의로 고르지 않고**
> 썸네일을 늘어놓고 고르시게 합니다.
>
> 받은 파일이 그림인 척하는 HTML(로그인 안내·오류 페이지)이면 **거부**합니다 — 실제 바이트를
> 열어 PNG/JPEG/WebP/GIF 인지, 치수가 읽히는지 확인합니다.

#### 도중에 앱이 꺼졌다면 (중단 후 이어가기)

작업 카드에 **어디서 멈췄는지**와 **다음에 무엇을 하면 되는지**가 함께 나옵니다.
새 작업을 만들지 않고 그 자리에서 이어갑니다.

| 멈춘 지점 | 다시 켰을 때 |
|---|---|
| **그림을 만드는 중** | 생성 전에 기록해 둔 화면 목록이 **그대로 남아 있습니다**. 그래서 다시 켠 뒤에도 광고·로고가 아니라 **새로 나타난 그림**만 후보로 봅니다. 생성 버튼을 무턱대고 다시 누르지 않고, **이미 만들어진 결과가 있는지 먼저 확인**합니다 |
| **캡션을 쓰는 중** | 「캡션을 쓰는 중에 앱이 종료되었습니다」라고 알리고 멈춥니다. **↻ 캡션 다시 만들기**(같은 그림 그대로) 또는 캡션을 직접 쓰고 **💾 이 캡션 사용** 중에 고르십시오. 저절로 다시 부르지 않습니다 |
| **올리는 중** | **올라갔는지 아닌지 알 수 없으므로 멈춥니다.** 그냥 이어가기는 막혀 있습니다(같은 글이 두 번 올라갈 수 있어서). **🔎 게시 여부 확인(읽기 전용)** 을 누르면 새 글을 올리지 않고 읽기만 해서 확인합니다. 확인이 안 되면 **✅ 이미 게시됨** / **▶ 게시 안 됨·이어가기** 를 직접 고르십시오 |

> **직접 쓴 캡션이 밀리지 않습니다:** 캡션을 손으로 쓰고 저장하면, 뒤늦게 도착한 자동 초안이
> 그것을 덮어쓰지 않습니다. 취소한 뒤 늦게 도착한 응답으로 게시가 시작되는 일도 없습니다.

> **자동 게시 선승인은 재시작으로 초기화되지 않습니다.** 남은 건수·기한·이미 쓴 작업 기록이
> 그대로 이어집니다 — 다시 켰다고 해서 한도가 되살아나거나 같은 작업이 다시 올라가지 않습니다.

> **왜 멈췄는지가 재시작 뒤에도 남습니다 (`rc.15`).** 예전에는 다시 켜면 어떤 작업이든
> 「재시작으로 중단됐습니다 — 이어서 진행할 수 있습니다」 한 줄로만 보였습니다.
> 로그인 화면에서 멈춘 것도, **결제처럼 되돌릴 수 없는 동작의 승인을 기다리던 것**도 똑같이
> 무해해 보였다는 뜻입니다. 이제 작업 카드가 멈춘 이유를 그대로 보여줍니다 —
> 🔐 로그인 필요 · 🧩 사람 확인 필요 · ⏸️ 승인 대기 · ⚠ 게시 여부 미확인 · 🔧 직접 처리 필요.
> 갈 곳이 있으면 그 버튼도 함께 남습니다.
>
> 사람이 직접 해야 하는 경우 버튼 문구가 **「▶ 처리했습니다 — 이어가기」** 로 바뀝니다.
> **이어가기를 눌러도 자동으로 승인되지 않습니다** — 위험한 동작이면 다시 물어봅니다.
> 비밀번호나 보안 승인이 저절로 처리되는 경로는 없습니다.

> **올리는 중에 오류가 나면 "재시도 중" 이 아니라 바로 물어봅니다 (`rc.15`).**
> 게시 버튼을 이미 눌렀는데 그 결과를 못 본 상태라면, 서버에는 이미 올라갔을 수 있습니다
> (응답만 유실된 경우). 그때 저절로 다시 돌리면 같은 글이 두 번 올라갈 수 있으므로,
> 진행 중인 것처럼 보이게 두지 않고 **곧바로 확인을 구합니다**.
> 반대로 **아직 아무것도 올리지 않은 상태**의 일시적 네트워크 오류는 예전처럼 알아서 재시도합니다 —
> 재시도 자체를 꺼 버린 것이 아닙니다.

### ② 관심 블로그 댓글·좋아요

`내 블로그 주소`(또는 `주제`)를 넣으면 비슷한 글을 찾아 **본문을 읽고** 그 내용에 맞는 댓글을
씁니다. `다룰 글 수`·`글 사이 간격`·`대상 사이트`·`댓글/좋아요 여부`를 직접 정하십니다.

건너뛰는 것: **내 블로그 글**, 제외하신 사이트, **본문을 읽지 못한 글**(로드 실패·내용 없음),
이미 댓글을 단 글, **이미 좋아요가 눌린 글**(다시 누르면 취소되므로).

- **같은 글에 두 번 달지 않습니다.** (대상 주소 · 계정 · 행동)을 기록해 두고, 재시작한 뒤에도
  그 기록을 보고 건너뜁니다. 화면 아래 **활동 기록**에서 직접 확인하실 수 있습니다.
  **기록이 디스크에 확정되기 전에는 댓글·좋아요를 누르지 않습니다**(`rc.15`) — 누르는 순간
  전원이 나가도 그 사실이 남아 있어야, 다시 켰을 때 같은 글에 또 달지 않기 때문입니다.
  (예전에는 기록이 0.3초 뒤에 저장돼서, 그 사이에 앱이 꺼지면 같은 글에 다시 달 수 있었습니다.
  좋아요는 다시 누르면 **취소**되므로 더 나빴습니다.) 저장이 막히면 **누르지 않고 건너뜁니다** —
  했는지 모르는 채로 남기느니 안 하는 쪽이 낫기 때문입니다. `이 작업에서 N건까지` 같은 한도도
  같은 방식으로 지켜져, 중단 한 번으로 한도가 0 으로 되돌아가지 않습니다.
- **기본은 "초안만"** 입니다. 실제로 달려면 `실제로 달기` 를 고르셔야 합니다.
- **대상 사이트 목록이 화면에 보입니다.** 필요 없는 곳은 지우고 시작하십시오 — 그 목록 밖으로는
  나가지 않습니다.

> **어떻게 두 번 달리지 않나:** 지시로만 막지 않습니다. **댓글 등록·좋아요 버튼을 누르기 직전에
> 코드가 확인**해서, 이미 한 글이면·초안 모드면·"좋아요 취소" 로 보이면 **누르지 않습니다.**
> (지시만 있던 때에는 실제로 댓글이 두 번 달리고 좋아요가 취소됐습니다 — 검증에서 잡아 고쳤습니다.)
>
> **글 수·간격·기한도 코드가 강제합니다.** 정하신 "다룰 글 수"·"글 사이 간격"은 이제 AI 에게
> 부탁하는 문구가 아니라, **작업별 카운터를 디스크에 두고** 버튼을 누르기 직전에 확인합니다.
> 그래서 AI 가 지시를 무시하든, 작업이 중간에 멈췄다 **다시 이어지든**, 내부적으로 구간이 바뀌든

> **① 저장이 막혔는데도 글이 올라갔습니다.** 글을 올리기 직전에 "지금 무엇을 하려는지"를 디스크에
> 적어 두는 단계가 있는데, 디스크가 꽉 찼거나 파일이 잠겨 **그 적기가 실패해도 그대로 올렸습니다**.
> 그러면 나중에 앱이 꺼졌을 때 무슨 일이 있었는지 설명할 근거가 **하나도** 남지 않습니다.
> 이제는 저장이 확정됐을 때만 올립니다. 실패하면 **아무것도 올리지 않고** 확인 화면으로 되돌아가,
> 무엇이 막혔는지와 무엇을 하면 되는지를 보여 줍니다 — 고친 뒤 "게시"를 다시 누르면 그대로 이어집니다
> (아직 올라간 것이 없으니 중복 걱정도 없습니다).

> **② AI 가 "이미 올라갔어요"라고 말하기만 해도 완료로 닫혔습니다.** "게시 여부 확인"은 AI 가
> 계정 화면을 읽고 판단하는 기능인데, 그 판단을 **말 그대로** 믿었습니다. 그 한 줄은 페이지를 한 번도
> 보지 않아도, 로그인 화면에서도, 엉뚱한 계정에서도 나옵니다. 잘못 믿으면 **안 올라간 글이 '완료'로
> 닫히거나**, 반대로 "안 올라갔다"를 믿고 차단을 풀어 **같은 글이 두 번 올라갑니다**.
> 이제는 앱이 **같은 화면을 따로 대조합니다.** 그 사이트에서 그 캡션을 **실제로 봤을 때만** 완료로
> 확정하고, 영수증에 **어느 주소에서 무엇을 봤는지**를 함께 남깁니다. 못 봤으면 완료로 닫지 않고
> 이유를 보여 줍니다. 그리고 **"안 보인다"는 "안 올라갔다"가 아니므로** 차단을 자동으로 풀지 않습니다 —
> 직접 확인하신 뒤 "게시 안 됨 · 이어가기"를 누르시면 됩니다(그 버튼은 그대로입니다).
>
> 고치는 과정에서 같은 자리의 결함이 더 드러나 함께 고쳤습니다: **확인이 도중에 끊기거나 확인
> 기록이 사라지면 "확인하는 중…"에서 영원히 빠져나오지 못하던 것**, **"게시 안 됨 · 이어가기"를
> 눌러도 차단이 곧바로 다시 걸리던 것**(눌러도 아무 일이 없어 보였습니다), 계정 화면의 안내 문구가
> 길면 **진짜 올라간 글을 못 찾던 것**, 그리고 **아직 올리지 않고 입력만 해 둔 캡션이 "올라간 증거"로
> 오인될 수 있던 것**(작성창 안의 글은 이제 근거로 세지 않습니다).

> 지금까지 이 기능은 **한 번의 실행 안에서만** 정확했습니다. 세 가지가 앱의 기억(메모리)에만

>   알 방법도, 다시 시도할 버튼도 없었습니다). 지금은 「캡션을 쓰는 중에 앱이 종료되었습니다」라고
>   알리고, **같은 그림 그대로** 다시 만들거나 직접 써서 저장하실 수 있습니다.

> 실패, 수정 후에는 통과 — 같은 검사입니다). **세 번째(올리는 중 종료)는 코드는 들어갔지만

> 않았습니다. 그리고 저희가 보장하는 것은 **"증거 없이 다시 보내지 않는다"** 까지이지,
> 서버 쪽에서 "정확히 한 번" 이 되도록 만드는 것이 아닙니다.

> **`rc.7` 에서 고친 것 — 게시 단계가 실제로 게시 사이트까지 갑니다.**

> 브라우저가 탭을 게시할 사이트로 **옮기지 않고** AI 에게 "인스타그램이 아니면 이동하세요" 라고
> 말만 해 두었기 때문입니다. 그러면 작업이 기억해 둔 페이지(`about:blank`)와 실제 탭이 어긋나고,

> **실제 구독 AI 로 끝까지 돌려서 확인했습니다**(94초 · 게시 단계에서 AI 호출 7회):

> **게시는 정확히 1건**, 허용한 사이트 밖으로 나간 요청은 **0건**이었습니다.
