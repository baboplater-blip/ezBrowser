### 판정 기준을 바꾼 3곳 (숨기지 않고 기록)
고쳐진 제품을 옛 기준이 실패로 잡은 자리다. **전부 조건을 완화만 하지 않고 하나씩 추가**했다.

   드러났다**: 구간 done 과 사용자 중단이 거의 동시에 오면 `result` 에 완료 보고가 남아 화면에
   "중단됨 + 완료했습니다" 가 같이 보였다. → 제품은 중단이 결론임을 앞세우도록 고쳤고(정보는 괄호 보존),
   기준은 **"result 가 성공처럼 읽히면 결함"** 으로 바꿨다. 판정식 음성대조 4/4 로 검출력 확인.

   → `exhausted` 를 더하고, **"done 으로 보고하면 실패"** 조건을 추가했다.
3. **PS4** — 재시작 잔여를 `cancelled` 로 기대했다(사용자 중단과 크래시 중단이 구분 안 되던 옛 동작).

### SL17 — 빈 검사였던 것을 이번 실행에서 고쳤다

**문제**: 교차 출처 iframe 은 페이지 JS 로 읽을 수 없다. 처음 판정은 "읽어 보니 비어 있었다" 가
아니라 **"못 읽었다" 를 비어 있음으로 센 것**이었다 — 제품이 통째로 깨져도 똑같이 통과한다.

**고친 순서**:
1. 판정을 조였다 — 실제로 비밀번호 칸을 찾아 값을 읽었을 때(`read=true`)만 판정 → 즉시 **FAIL**
   (검사가 스스로 "나는 아무것도 못 봤다" 고 말하게 된 것이 1차 성과).
2. 근본 원인: **CDP 이벤트 구독자 시그니처를 틀렸다.** `build/lib/cdp.mjs` 구독자는
   `(_, method, params, sessionId)` 로 불리는데 `(msg) => msg.method` 로 썼다 →
   **아무 이벤트도 못 잡고 조용히 빈 손**. 예외가 안 나므로 눈에 띄지 않았다.
3. 읽는 경로를 세 갈래로: ① `Page.createIsolatedWorld`(같은 렌더러 자식 프레임)
   ② `Target.setAutoAttach` 자식 타깃 세션(OOPIF) ③ main-world 실행 컨텍스트.
   실제 채택 경로는 detail 에 찍는다(관측: `격리 월드(같은 렌더러)`).
4. **읽은 문서의 주소가 alt 출처인지까지 대조** — 엉뚱한 문서를 읽고 "비어 있다" 하는 경로 차단.
5. **양성 대조**: 같은 출처 iframe 은 반대로 자동 입력이 **되어야** 한다(관측: `user="demo-user"`).

> 교훈: **"안 보였다" 를 "없었다" 로 세지 마라** — 못 읽었다는 사실 자체를 판정에 넣어야 한다.
> 공유 라이브러리의 콜백 시그니처는 추측하지 말고 소스에서 확인할 것(틀려도 조용히 통과한다).

우리 도구를 쓰는지*는 증명되지 않는다. 그래서 실제 앱 + **사용자 기존 구독 Claude CLI** + 로컬 픽스처로
따로 돌린다. 외부 사이트 접속·유료 키·크레딧 사용 **0**. 구독 한도 때문에 **게이트에 등록하지 않는다**(수동).

**판정은 모델이 한 말이 아니라 픽스처 서버가 관측한 `/state` 로 한다.** **2 PASS / 0 FAIL**.

| id | 합격(사용자가 보는 동작) | 결과 | 예산 사용 |
|---|---|---|---|
| **R-SNS** | 이미지 생성 → 생성물 가져오기 → 캡션 → SNS 게시 완료 | ✅ PASS | **14단계 / 14호출 / 138초** (한도 20) |
| **R-BLOG** | 서로 다른 2글에 본문 근거 댓글 + 좋아요, 중복·내 글 0 | ✅ PASS | **8단계 / 7호출 / 39초** (한도 20) |

**R-SNS 증거**(서버가 받은 것): 산출물 1개 · **업로드 바이트 일치 = true**(`art_fe9cbb6f52eb`, 7,056바이트) ·
서버 게시 1건 · 캡션 비어 있지 않음 — 모델이 쓴 캡션
`"별이 쏟아지는 밤, 호수 위에 떠 있는 작은 나룻배 한 척 🌌 #수채화 #밤하늘"`.
모델이 실제로 한 일: 기존 이미지 5개(로고·광고·썸네일)를 **기준선으로 기록** → 프롬프트 생성 →
**새로 나타난 결과 이미지만** 산출물로 저장 → 첨부 → 업로드 완료 대기 → 공유.
즉 `mark_baseline` · `capture_image` · `upload_file(artifact)` · `wait_for` 를 **실제 플래너가 썼다**.

**R-BLOG 증거**(서버가 받은 것): 새 댓글 **2건**이 **서로 다른 글**(`post:2`, `post:4`)에 ·
좋아요 **둘 다 true** · **내 블로그 글에 단 댓글 0건**. 모델이 본문(8문단)을 읽고 그 내용에 근거해 댓글을
썼고, 좋아요가 안 눌린 것만 눌렀다고 보고했으며 서버 상태가 이를 뒷받침한다.

**앞선 실행(run1)에 대하여 — 숨기지 않는다**: run1 은 **하네스 결함**으로 실패했다.
작업자가 `onAgentEvent` 구독을 빠뜨려 이벤트를 하나도 못 받고 `steps=0 calls=0 timeout=true` 로 봤다.
**그동안 앱은 정상 진행 중**이었고 그 프로필(`verify-out/social-realmodel-run1/profile/ai-agent-runs.json`)에
`status=done · 47단계` 로 SNS 게시를 완주한 기록이 남아 있다 — **앱이 멀쩡했다는 증거다**.
그 실행 중 `The model's tool call could not be parsed` 1건도 관측됐으나 표본 1건이라
**일시적 파싱 실패로 기록**하고, 수정 뒤 run2 는 재시도 없이 1차 통과했다(`retried=false`).
결정적 앱 결함이라는 증거는 없다.

> **교훈**: "검사가 아무것도 못 봤다" 와 "앱이 아무것도 안 했다" 는 다르다 —
> SL17 때와 같은 부류다(못 읽은 것을 없는 것으로 세지 말 것). 이번엔 앱이 남긴 실행 이력이
