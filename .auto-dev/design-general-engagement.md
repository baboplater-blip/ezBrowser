# 일반 영속 작업의 댓글·좋아요 보호 (2026-09-20)

## 확인된 공백

`agent.ts:1398` 의 참여 가드는 **`parseEngageMark(task)` 가 표식을 찾았을 때만** 돈다. 그 표식은
블로그 참여 워크플로(`buildBlogEngageTask`)가 붙인다. 따라서 사용자가 AI 패널에 직접 쓴
**일반 영속 작업**("이 글에 댓글 달아줘")은 그 가드를 **한 줄도 지나지 않는다**.

`task-runtime.ts:1169` 의 외부 쓰기 원장도 `isPublishAction(label)` 만 기록한다 — 댓글 등록·
좋아요는 발행 정규식에 걸리지 않으므로 **불확실 대기(`waitCause 'ledger'`)도 발동하지 않는다.**

결과(재현 대상):
- **응답 유실**: 댓글이 서버에 반영됐는데 모델 응답만 유실 → 구간이 오류로 끝남 → 재시도 →
  **같은 댓글이 두 번** 달린다.
- **크래시/재시작**: 좋아요가 반영된 뒤 앱이 죽음 → 재시작 후 이어가기 → 같은 버튼을 다시 누름 →
  **좋아요가 취소(toggle off)** 된다.

## 원칙 (하지 않는 것)

1. **모든 사이트 보장을 주장하지 않는다.** 식별 가능한 댓글·좋아요만 다룬다.
2. **모든 클릭을 막지 않는다.** 분류가 null 이면 기존 흐름에 손대지 않는다.
3. **전역 `default` 계정 장부에 쓰지 않는다.** 서로 다른 세션이 한 바구니로 뭉개진다.
4. **프로즈 정규식을 넓히지 않는다.** 구조적 행동 메타데이터(요소 tag/type/state·초안 유무)로 판정을
   좁히고, 기존 어휘 정규식은 **씨앗**으로만 쓴다.
5. **중앙 게이트 유지.** 새 분기는 기존 참여 가드와 같은 자리(위험 게이트·취소 관문 뒤)에 둔다.

## 설계

### ① 범위 (scope)

```
generalScope = params.taskId && !readOnly && !engageGuard  →  `task:<taskId>`
```
- **작업 단위**다. 재시도·크래시 재시작은 같은 작업 id 로 이어지므로 정확히 그 창을 덮는다.
- 다른 작업·다른 계정·다른 세션과 절대 섞이지 않는다(`default` 버킷 미사용).
- 비영속(일회성 챗 에이전트)에는 적용하지 않는다 — 구간·재시작 개념이 없어 보호할 대상이 없다.

### ② 구조적 분류 — `classifyEngageAction()` (agent-gate.ts)

입력: `{ label, el: {tag,type,name,state} | null, clickAtTag, hasDraftText }`

1. **`state === 'checked'` 인 좋아요류 → `unlike`**(구조적 — 라벨보다 우선). 이미 켜진 토글을
   누르면 꺼진다는 사실은 라벨이 아니라 상태가 말해 준다.
2. 어휘 `UNLIKE_RE` → `unlike`.
3. 어휘 `COMMENT_SUBMIT_RE` → **두 구조 조건을 모두 통과해야** `comment`:
   - 제출 가능한 컨트롤인가(`button` / `input[type=submit|button]` / `role=button`).
     `<a>` 링크면 **작성창 열기**로 보고 분류하지 않는다.
   - 화면에 입력된 댓글 초안이 있는가(`hasDraftText`). `false` 면 작성창 열기로 본다.
     판별 불가(`undefined`)면 강등하지 않는다(보수적).
4. 어휘 `LIKE_RE` → `like`.

### ③ 대상 식별 — `probeEngageTarget()` (page-actions.ts)

클릭 대상에서 위로 올라가며 **그 글의 정체**를 찾는다.
1. 조상 중 현재 페이지와 다른 http(s) 퍼머링크 `<a href>` → `permalink` (최우선).
2. 없으면 조상의 제목(`h1~h4`) → `heading` 지문.
3. 둘 다 없고 페이지가 목록형(listHint count ≥ 2)이면 → **ambiguous**.
4. 목록형이 아니면 페이지 주소 자체를 키로 쓴다(단일 글 페이지).

키: `permalink` → `normalizeTargetUrl(permalink)`,
`heading` → `normalizeTargetUrl(pageUrl) + '#h=' + sha1(heading)`.

**ambiguous → `ask` 로 일시정지**(기존 `waitCause 'ask'` 경로). 사용자가 답하면 이어간다.
거짓 완료로 넘어가지 않는다.

### ④ 판정과 기록 (agent.ts, 참여 가드 바로 뒤)

- `unlike`:
  - 이 작업이 그 글에 **좋아요를 기록해 두었다** → **차단**(우리가 누른 것을 우리가 취소하는 경로 —
    응답 유실·재시작의 전형).
  - 기록이 없고 **작업 지시가 명시적으로 취소를 요청**했다면 → **허용**(의도된 취소를 막지 않는다).
  - 그 외 → 차단(사용자가 예전에 눌러 둔 좋아요를 말없이 풀지 않는다).
- `comment` / `like`:
  - `alreadyDid(key, scope, kind)` → **차단**.
  - 통과 → `recordEngagement` + **`persistEngageBoundary()`**(클릭 전 동기 확정).
    확정 실패 → **클릭하지 않는다**(저장 실패 시 부작용 0).

### ⑤ 불확실 원장 — 구조적 메타데이터로 (task-runtime.ts)

`agent.ts` 가 `action` 이벤트에 **`external: 'publish'|'comment'|'like'`** 를 실어 보낸다.
`task-runtime` 은 그 필드가 있으면 기록하고(정확), 없으면 기존 `isPublishAction(label)` 로 폴백한다
(옛 경로 무변경). 원장 항목에 `kind` 를 두어 대기 문구를 맞게 쓴다 —
댓글인데 "발행이 됐는지 확실하지 않습니다" 라고 묻던 것을 고친다.

## 리뷰 후 보강 (2026-09-20, 코드 리뷰 + e2e 가 찾은 것)

| # | 무엇이 틀렸나 | 어떻게 고쳤나 |
|---|---|---|
| H1 | `"좋아요 취소하지 마"` 가 **취소 요청**으로 읽혔다(막으라는 일을 허용) | 매치 앞뒤 ±20자에 부정 표현이 있으면 요청으로 보지 않는다. 애매하면 허용하지 않는 쪽 |
| H2 | 구조 규칙이 **`aria-pressed` 를 못 읽었다** — 관찰 스키마에 없다. 가장 흔한 좋아요 마크업에서 사망 | 페이지 조사에서 직접 읽는다. `click_at` 에도 적용된다(관찰 요소가 아예 없는 경로) |
| H3 | 기록이 가드 안에서 일어나, 그 뒤의 **중복 게시 확인·발행 금지·막힘 감지** 가 `continue` 하면 **클릭은 안 나갔는데 장부에는 처리됨**으로 남았다(영구 과차단 + 거짓 안내) | 가드는 **결정만** 하고, 기록은 **실행 직전** 한 자리에서. 새 분기가 늘어도 새지 않는다 |

| H5 | 댓글이 달리면 안쪽에 **작성자 프로필 링크**가 생겨 신원이 바뀌었다. 제목 키에 `?comment=` 같은 쿼리가 섞였다 | 제목 안의 링크 우선 → 없으면 **가장 바깥** 글 덩이의 링크. 제목 키는 쿼리를 뺀 주소 기준 |

| M2 | contenteditable 은 관찰에 값이 안 실려 "초안 없음" 으로 읽혔다 → 보호가 **조용히 꺼졌다** | 값을 관찰할 수 없는 종류는 "빈 칸" 의 근거로 세지 않는다(모르면 모른다) |
