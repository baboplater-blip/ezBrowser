## 1. 변경 전 / 변경 후

| | 변경 전 | 변경 후 |
|---|---|---|
| 로그인 화면을 만나면 | 에이전트가 **무조건 멈추고** 사람에게 넘겼다(SEC 라운드의 인계 설계) | 사용자가 **그 계정에 대해 명시로 켠 경우에만** 브라우저가 직접 로그인하고 **원래 작업을 이어간다** |
| 비밀번호 저장 | 저장만 있고 자동화와 연결되지 않았다 | 저장은 그대로, **자동화 허용은 별도 플래그**(`autoLoginAllowed`) — 저장했다는 사실만으로는 절대 로그인하지 않는다 |
| 계정이 여럿일 때 | — | 기본 계정(`preferred`)이 없으면 **아무것도 입력하지 않고 묻는다** |
| 비밀번호가 틀리면 | — | 실패를 누적하고 3회에서 **잠근다**(사이트 계정 잠금 방지). 비밀번호를 고치면 풀린다 |

**핵심 설계 — 저장과 자동 제출을 분리했다.** 비밀번호 관리자에 값이 있다는 것과 "로봇이 그 값을
대신 넣고 로그인 버튼까지 눌러도 된다"는 전혀 다른 동의다. 후자는 계정마다 따로 켜야 하고,
기존에 저장돼 있던 항목은 마이그레이션에서 **전부 꺼진 상태**로 들어온다.

## 3. 한계 (숨기지 않고 적는다)

1. **실제 웹사이트에서 시험하지 않았다.** 확인한 것은 로컬 HTTPS 픽스처뿐이다. 네이버·구글·
   인스타 같은 실사이트의 로그인 폼은 구조가 제각각이라, 안 맞으면 **입력하지 않고 사람에게 넘긴다**
   (안전한 방향으로 실패한다) — 하지만 "실사이트에서 성공한다"는 주장은 하지 않는다.
2. **CAPTCHA·2단계 인증(OTP)은 대신 처리하지 않는다.** 감지하면 멈추고 사람에게 넘긴다(설계).
3. 저장된 비밀번호 자체의 보호는 기존 `safeStorage`(OS 수준 암호화) 그대로다. 이번 라운드가
   바꾼 것은 **자동화가 그 값을 쓸 수 있는 조건**이지 저장 방식이 아니다.
4. 아래 셋은 이번 요청과 **무관하게** 이전부터 남아 있는 미검증 항목이다:
   코드 서명(.pfx 없음 — SmartScreen 경고) · 외부 clean Windows PC 설치·자동업데이트 수신 ·
   실제 24시간 연속 실행(실제 시계 증거는 25.8분이 최대).

## 4. 재시도 기록 — 두 번 막혔고 어떻게 풀었나

### (1) 앞 실행이 1시간 제한에 걸려 중단됐다
`run-20260918T101236Z-5d0d33` 이 3600초 제한으로 끊겼다(완료 기록 없음). 구현·회귀·설치 검증은
이미 끝나 있었고, **처음부터 다시 하지 않고** 마지막 지점(SL17 보강)만 이어서 마감했다.
그 실행의 사용량은 `result` 이벤트가 없어 **미계측**이다 — 0 으로 채우지 않았다.

### (2) SL17 이 "빈 검사"로 통과하고 있었다 — 이번에 고친 것

SL17 은 *"페이지 안의 다른 출처 iframe 이 최상위 페이지의 저장 계정을 가져가지 못한다"* 를 본다.
그런데 **교차 출처 iframe 은 페이지 JS 로 읽을 수 없다.** 처음 판정은 "읽어 보니 비어 있었다"가
아니라 **"못 읽었다"를 비어 있음으로 센 것**이었다 — 기능이 통째로 깨져도 똑같이 통과하는 검사다.

고친 순서:

1. **판정을 조였다** — `alt.read`(실제로 비밀번호 칸을 찾아 값을 읽었다)가 참일 때만 판정한다.
   → 곧바로 **FAIL**. 검사가 스스로 "나는 아무것도 못 봤다"고 말하게 된 것이 1차 성과다.
2. **왜 못 읽었나** — CDP 로 프레임 안에서 평가하려 했는데, 이벤트 구독자 시그니처를 틀렸다.
   `build/lib/cdp.mjs` 의 구독자는 `(_, method, params, sessionId)` 로 불리는데 `(msg) => msg.method`
   로 썼다 → **아무 이벤트도 못 잡고 조용히 빈 손**. 이것이 근본 원인이었다.
3. **읽는 경로를 세 갈래로** — ① `Page.createIsolatedWorld`(같은 렌더러의 자식 프레임)
   ② `Target.setAutoAttach` 로 붙은 **자식 타깃 세션**(별도 프로세스 OOPIF)
   ③ main-world 실행 컨텍스트. 어느 경로든 **비밀번호 칸을 실제로 찾았을 때만** 읽었다고 친다.
   detail 에 어느 경로로 읽었는지(`[격리 월드]` 등)를 찍어, 앞으로 빈 검사가 되면 눈에 보이게 했다.
4. **양성 대조를 붙였다** — 같은 출처 iframe 은 **자동 입력이 되어야** 한다. 이게 없으면
   "전부 안 채워져서" 통과한 것과 구분되지 않는다.

> 교훈: **"안 보였다"를 "없었다"로 세지 마라.** 못 읽었다는 사실 자체를 판정에 넣어야 한다.
> 그리고 공유 라이브러리의 콜백 시그니처는 추측하지 말고 소스에서 확인할 것 —
> 틀려도 예외가 안 나고 **조용히 통과**한다.
