# 생성물 파이프라인 · 이미지 만들어 SNS 게시 · 관심 블로그 댓글/좋아요 (2026-09-18)

> 이 문서는 **이번 라운드에서 실제로 동작하게 만든 것**과 **확인하지 못한 것**을 가른다.
> 검증 범위 밖의 것을 완료로 쓰지 않는다.

## 1. 무엇이 없어서 안 됐나 (출발점)

요청은 "AI 로 그림을 만들어 → 캡션을 붙여 → 내 SNS 에 올려라" 였는데, 그 사이가 **끊겨 있었다**.

| 끊긴 곳 | 증상 |
|---|---|
| `download` 액션이 **시작만 하고 결과를 몰랐다** | 파일이 저장됐는지·실패했는지 판정 불가. 곧바로 "이제 업로드하세요" 로 넘어가 **빈 손으로** 다음 단계를 밟았다 |
| `upload_file` 이 **사용자 지정 자료 폴더에서만** 파일을 찾았다 | 방금 만든 그림을 사람이 손으로 그 폴더에 옮겨야 했다 |
| 생성물을 **가려낼 방법이 없었다** | 화면에는 로고·광고·썸네일·이전 결과가 이미 잔뜩 있다. "이미지 하나 가져와" 로는 광고를 집는다 |

## 2. 만든 것

### A. 작업별 격리 산출물 저장소

- `app/main/features/ai/artifacts.ts` — `<userData>/agent-artifacts/<taskId>/`.
  메타: `id · 형식 · 바이트 · sha256 · 치수 · sourceUrl · sourcePageUrl · sourceTabId · sourceFrameUrl · 시각 · origin`.
- **실제 바이트 검증** (`probeImage`): 확장자·Content-Type 을 믿지 않고 매직 바이트로 PNG/JPEG/WebP/GIF
  를 판별하고 **치수까지 디코딩**한다. 다음은 거부한다 —
  **HTML 위장**(`<!doctype`/`<html`/`<?xml`, 대소문자·선행공백 무관), **빈 파일**, 잘린 파일, 치수 0,
  50MB 초과. (토큰 CDN 이 Referer 없으면 `403 text/html` 을 주는데, 그걸 이미지로 저장하면 그대로
  SNS 에 올라간다 — 실제로 일어나는 사고다.)
- **경계**: `resolveArtifactPath` 가 realpath 까지 풀어 **그 작업 폴더 안일 때만** 경로를 준다.
  다른 작업·폴더 밖·심링크 탈출은 전부 `null`.

### B. 생성물 가려내기 (`capture.ts` + 에이전트 액션)

- **기준선(baseline)** — (작업, 탭)별로 "생성 전에 화면에 있던 이미지 주소"를 기록.
  `navigate`·`open_tab` 때 **자동으로도** 기록한다(모델이 `mark_baseline` 을 잊어도 동작).
- `capture_image` 는 **기준선 이후 새로 생긴 것**만 후보로 본다. 추가 거부 규칙:
  - 가로·세로 어느 쪽이든 **256px 미만 제외** (로고·아이콘·아바타·썸네일)
  - **현재 조작 탭만** — 다른 탭의 이미지는 보지 않는다
  - 허용 사이트 밖 프레임은 애초에 스크립트를 돌리지 않는다(텍스트 0글자 유출)
  - 후보가 **둘 이상이면 자동 선택하지 않는다** — 목록을 주고 `index` 를 요구하고, 확신이 없으면
    사용자에게 묻도록 지시한다
  - 기준선 이후 새 것이 없으면 막다른 길로 만들지 않되(`fallback`), 그 경우 **자동 채택을 금지**한다
- **바이트를 받는 경로 두 가지**:
  - `http(s)` → **메인 프로세스가 탭 세션으로** 받는다 → 로그인 쿠키 유지 + Referer 동봉(핫링크 차단 CDN)
  - `blob:` / `data:` / `canvas:` → 그 문서 안에서만 유효하므로 **페이지 컨텍스트**에서 읽는다
  - 어느 쪽도 페이지가 막아 둔 것을 뚫지 않는다. tainted canvas 는 우회하지 않고 그대로 실패로 알린다.
- **`download` 는 이제 완료까지 기다린다** — 완료·실패·타임아웃·취소를 판정하고, 끝난 파일을 작업
  산출물로 **복사**한다(사용자 다운로드 폴더의 원본은 지우지 않는다).
  이벤트와 폴링을 **둘 다** 쓴다(실패 경로가 항상 이벤트를 내지 않아, 이벤트만 믿으면 실패한 다운로드를
  타임아웃까지 기다린다).
  파일이 **이미지처럼 보이면**(확장자·MIME) 바이트 검증을 강제하고, 그 밖(영상·압축)은 그대로 받는다.
- **업로드 연결**: `{"action":"upload_file","artifact":"art_..."}` — 폴더로 옮길 필요가 없다.
- **정지·취소 뒤에는 파일이 넘어가지 않는다**: `capture_image`·`upload_file`·`download` 모두
  부작용 직전에 관문을 통과한다(이번 라운드에서 `upload_file`·`download` 에 **없던 것을 추가**했다).

### C. 생성 → 확인 → 게시 워크플로 (`social-workflow.ts` + UI)

3단계. **게시는 사용자가 누를 때만 시작된다.**

| 단계 | 하는 일 | 다음으로 가는 조건 |
|---|---|---|
| `generate` | 생성 사이트에서 이미지 생성 → 산출물 저장 | 산출물 1개면 자동, **여럿이면 사용자가 고른다** |
| `review` | **이미지 미리보기 + 캡션 초안**(수정 가능) | **사용자가 "이대로 게시" 를 눌러야만** |
| `publish` | `buildSnsTask` 레시피로 게시 | 완료 신호 확인 → 영수증 |

- **중복 게시 방지**: 게시 작업을 만드는 코드 경로가 `runPublishStage` **하나뿐**이고, 그것은
  `approveAndPublish` 에서만 불린다. 부팅 복원(`initSocialWorkflows`)은 상태를 **읽기만** 한다.
  추가로 `stage !== 'review'` 이거나 **이미 영수증이 있으면** 승인을 거부한다.
- **불확실한 게시를 완료로 쓰지 않는다**: 작업이 `needs-verify` 로 끝나면 `done` 으로 넘기지 않고
  영수증에 "완료 신호 미확인" 을 남기고 `publish` 에 머문다(UI 는 주의 색으로 표시).
- **산출물은 게시 작업 폴더로 복사해서 쓴다** — "다른 작업 폴더를 넘겨다보는 예외" 를 만들지 않으려고.
- 작업 생성 뒤 지시문에 산출물 id 를 넣어야 해서(id 는 작업을 만들어야 정해진다) `setTaskInstruction`
  을 task-runtime 에 **공식 API 로 추가**했다. **시작한 작업은 거부**한다(도는 구간이 옛 지시문을 들고
  있으면 같은 작업의 두 구간이 다른 지시를 따른다).

### D. 관심 블로그 댓글·좋아요 (`blog-engage.ts` + UI)

- **본문을 실제로 읽게** 한다. 본문이 짧거나(기본 300자 미만) 로드 실패면 **그 글은 건너뛴다.**
  댓글은 **본문의 구체적인 대목을 언급**하도록 지시하고, "좋은 글 잘 보고 갑니다" 류 상투 댓글을 금지한다.
- **중복 방지 장부**: (정규화된 대상 주소 · 계정 · 행동) 키. 재시작해도 남는다.
  정규화는 `utm_*`·`fbclid`·해시·`www.`·끝 슬래시·스킴 차이를 흡수하되 **쿼리는 정렬해 보존**한다
  (글 id 가 쿼리에 있는 블로그가 많아, 지우면 서로 다른 글이 같은 키가 된다).
- **좋아요 취소 사고 방지**: 화면에 "좋아요 취소"·"공감 취소" 로 보이면 누르지 않는다.
- 건너뜀: 내 블로그 글 · 제외 사이트 · 읽지 못한 글 · 이미 댓글 단 글 · 이미 좋아요된 글.
- 사용자가 정하는 것: **글 수 · 글 사이 간격 · 대상 사이트 · 계정 · 댓글/좋아요 여부 · 초안/실행**.
  대상 사이트 목록은 화면에 칩으로 보이고 지울 수 있다(빈 목록이면 시작을 막는다 — 빈 배열은
  "제한 없음" 이라 범위가 통째로 열린다).
- **요청하지 않은 행동 금지**: 팔로우·이웃추가·쪽지·DM·가입·결제를 하지 않도록 지시문에 명시.
- **프롬프트 인젝션**: 블로그 본문은 데이터일 뿐 지시가 아니라고 명시하고, 본문 속 지시를 따르지 않게 한다.
  (관찰 본문은 이미 신뢰 경계로 감싸여 있고, 허용 사이트·자료 범위는 **코드**가 강제하므로 본문이
  그 범위를 넓히지 못한다.)

| C2 | 같은 글에 댓글이 **2번** 달렸다 |
| C3 | 이미 좋아요된 글에서 다시 눌러 **좋아요가 취소됐다** |
| C6 | **초안 모드인데** 댓글이 등록되고 좋아요가 눌렸다 |

원인은 하나다. 방지가 전부 **지시문 수준**이었다 — 장부는 기록만 하고 **아무도 조회하지 않았고**,
초안 모드는 발행 금지 표식에 기댔는데 "댓글 등록" 은 발행성 클릭으로 분류되지 않았다.
**장부에 적기만 하고 행동을 막지 않으면 그것은 방지가 아니다.**

**판정을 코드로 옮겼다**: `agent-gate.ts` 에 분류기·표식을 두고, 레시피가 표식을 싣고,
에이전트 루프가 **클릭 직전에** 막는다 — 취소성 좋아요 거부 / 초안 모드 거부 / 사용자가 고르지 않은
행동 거부 / 장부에 이미 있으면 거부. 통과한 것만 **실행 직전에** 기록한다(클릭 뒤에 적으면 실패·중단
시 기록이 빠져 다음에 또 단다). 분류기는 **취소를 먼저** 본다 — "좋아요 취소" 를 좋아요로 읽으면
눌러서 풀린다. 댓글은 등록 동사가 함께 있을 때만 제출로 본다("댓글 3개" 오탐 방지).

### 4-3. 통합하면서 내가 찾아 고친 결함 5건

| # | 무엇이 잘못됐나 | 왜 위험한가 |
|---|---|---|
| 1 | `upload_file` 이 **정지·취소 관문을 지나지 않았다** | 정지를 눌러도 파일이 페이지로 넘어간다 |
| 2 | `download` 는 취소만 보고 **정지를 무시**했다 | 정지 중에도 파일이 계속 내려온다 |
| 3 | 다운로드 가져오기가 `expect:'any'` 라 **형식 검증을 통째로 건너뛰었다** | `.png` 주소가 준 HTML 이 산출물이 되어 게시된다 |
| 4 | `download` 의 **모델이 써 넣은 url 에 허용 사이트 검사가 없었다** | 본문에 심어 둔 지시가 범위 밖 파일을 끌어와 게시될 수 있다(프롬프트 인젝션이 **파일 범위**를 넓히는 경로) |
| 5 | 작업 생성 뒤 지시문을 **저장소 객체 직접 변경**으로 바꿨다 | 구현이 언젠가 복사본을 돌려주면 자리표시자가 그대로 나간다 → `setTaskInstruction` 공식 API 로 교체 |

4번은 "페이지에서 고른 것(ref·감지 후보)" 과 "모델이 문자열로 써 넣은 주소" 를 구분해서 막았다.
전자는 그 페이지가 이미 불러온 하위 리소스라 CDN 호스트가 달라도 정상이기 때문이다(전부 막으면
정상 다운로드가 깨진다).

|---|---|

**설치→부팅→제거 검증은 이 머신에서 실행하지 못했다.** `verify-install` 이 스스로 `BLOCKED` 를
냈다 — 이 PC 에 **사용자가 실제로 쓰는 ezBrowser 설치본**이 등록돼 있고
(`%LOCALAPPDATA%/Programs/browser-build`), 이 검사는 무인 설치·무인 제거를 하므로 계속하면
그 설치를 덮어쓰거나 지운다.
**우회하지 않았다** — 사용자의 실제 앱을 보존하는 것이 검사보다 우선이다. 대신 **패키징된 rc.4 앱이
실제로 부팅해 스모크 16종을 통과**하는 것은 확인했다(`dist/win-unpacked/ezBrowser.exe`).



### 4-5. 발견했으나 **이번에 고치지 않은** 결함 (범위 밖 — 기록만)

- `writeDownloadMd`([conversations.ts](../app/main/features/ai/conversations.ts))가
  `settings.downloads.defaultPath` 를 무시하고 **항상 OS 기본 다운로드 폴더**에 쓴다. 그래서 격리
  프로필로 도는 검증이 **실사용자 Downloads 폴더에 파일을 만든다**(하네스가 만든 6개는 확인 후 삭제).
  보고서 저장 경로 설정이 실제로는 안 먹는다는 뜻이기도 하다. 별도 라운드에서 고칠 것.

## 5. 확인하지 못한 것 (솔직하게)

- **Genspark · ChatGPT 의 실제 화면 흐름은 시험하지 못했다.** 로그인과 생성 크레딧이 필요해
  자율 수행 범위 밖이다. 공개 정보로 확인한 것은 **진입 주소와 "이미지 생성이 워크스페이스 안에
  있고 고정된 단독 URL 이 아니다"** 는 점까지다. 그래서 레시피는 화면에서 생성 기능을 찾지 못하면
  **헤매지 않고 사용자에게 묻도록** 되어 있다. 각 제공자에서의 성공은 **미검증**이다.
- **실제 SNS 계정 게시·실제 블로그 댓글은 하지 않았다.** 검증은 전부 로컬 픽스처에서 했다.
- **"글 사이 간격" 은 지시문 수준**이다 — 모델에게 기다리라고 요청할 뿐, 코드가 강제하지 않는다
  (댓글 등록은 일반 클릭으로 나가므로 어느 클릭이 '등록' 인지 코드가 알 수 없다).
- 이전 라운드부터 남아 있는 것(이번 범위 밖): 코드 서명 없음(SmartScreen 경고) · 외부 PC 미검증 ·
  실제 24시간 연속 실행 미실시.
